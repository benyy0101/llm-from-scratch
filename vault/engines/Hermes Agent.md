# Hermes Agent

Nous Research가 만든 오픈소스 셀프호스팅 에이전트 플랫폼입니다. [[Cline]]·[[Continue.dev]]가 "IDE 확장 하나"라면, Hermes는 **코딩 에이전트 기능을 포함하면서 그보다 훨씬 넓은 범위(개인비서·리서치·자동화)까지 아우르는 상위 카테고리**에 가깝습니다.

## 철학 — "개인 AI 운영체제"

Hermes는 스스로를 "개인 AI 운영체제(personal AI OS)"로 소개합니다. 이 표현이 가리키는 설계 원칙 세 가지:

1. **에이전트는 하나의 작업 세션이 아니라 지속되는 존재다** — [[함수 호출 (Tool Use)|Cline/Continue.dev]]는 대화·워크스페이스가 끝나면 컨텍스트가 리셋되는 게 보통이지만, Hermes는 **데몬(daemon)에 상태를 저장**해 프로젝트를 넘나들며 사용자를 계속 기억합니다.
2. **에이전트는 여러 정체성으로 나뉠 수 있다** — 코딩 에이전트, 개인비서, 리서치 에이전트가 한 프로세스 안에서 상태 섞임 없이 공존합니다([[#Profiles]] 참고).
3. **에이전트는 스스로를 개선한다** — [[#GEPA]]처럼 프롬프트를 자동으로 진화시키는 메커니즘을 내장했습니다. 다만 이 자기개선이 항상 옳은 방향은 아니라는 게 문서에도 명시돼 있어([[#GEPA]] 참고), "완전 자율 개선"보다는 "감독이 필요한 자기개선"에 가깝습니다.

## 코딩 에이전트로서의 위치

**ACP(Agent Client Protocol)**를 통해 VSCode·Zed·[[Continue.dev|JetBrains]]까지 연결되어, 자율적으로 파일을 계획·수정하고 diff를 승인받고 터미널을 실행하는 흐름은 [[Cline]]과 같은 범주입니다. 차이는 그 위에 메모리·멀티에이전트 위임·다른 도구들이 얹혀 있다는 것.

| | [[Cline]] | [[Continue.dev]] | Hermes |
|---|---|---|---|
| IDE 지원 | VSCode만 | VSCode + JetBrains | VSCode + Zed + JetBrains (ACP로 범용) |
| 메모리 범위 | 세션/워크스페이스 단위 | 세션 단위 | 프로젝트를 넘나드는 영속 메모리(데몬 저장) |
| 성격 | 코딩 전용 자율 에이전트 | 자동완성 + 채팅 중심 | 코딩을 포함하는 범용 에이전트 플랫폼 |

## 기능 목록

- **Profiles** — 프로필마다 독립된 `config.yaml`·`.env`·메모리·세션·스킬·크론·상태DB를 가짐. 코딩용/개인비서용/리서치용 에이전트를 상태 섞임 없이 동시 운영.
- **SOUL.md** — 프로필별 에이전트 성격(정체성)을 정의하는 문서. 일반 시스템 프롬프트보다 더 깊은 레벨의 커스터마이징.
- **메모리** — 내장 메모리 + 외부 백엔드(Mem0, Honcho 등) 연동으로 세션을 넘는 사용자 모델링.
- **Kanban** — 태스크를 여러 서브에이전트에 배분·추적하는 멀티에이전트 오케스트레이션 레이어. 단일 에이전트 도구를 멀티에이전트 플랫폼으로 끌어올리는 핵심 기능.
- **Cron** — 게이트웨이 데몬이 60초마다 체크하며 예약 작업을 격리된 세션에서 실행, 결과를 메신저로 전달.
- **Skills** — 반복 작업 절차를 재사용 가능한 단위로 저장. 안 쓰는 스킬은 아카이브로 이동, 한 명령으로 복구 가능.
- **GEPA(Genetic-Pareto Prompt Evolution)** — 에이전트가 스스로 프롬프트를 개선하는 메커니즘. 자기 과대평가나 수동 설정을 덮어쓰는 부작용이 알려져 있어 검토가 필요.
- **Voice Mode** — [[faster-whisper|로컬 Whisper(STT)]] + TTS로 음성 대화. 변환된 텍스트는 이후 일반 에이전트 파이프라인(메모리·도구·스킬)에 그대로 들어감. API 키 없이 로컬에서만 처리돼 폐쇄망에 적합.
- **Gateway** — 슬랙 등 메신저 플랫폼과의 연동 창구.
- **Tool Search / Curator** — 필요한 도구를 동적으로 찾아 불러오고, 메모리·스킬을 백그라운드에서 정리.

## 잘 맞는 모델 — "헤르메스에는 헤르메스 모델"이 아니다

직관과 달리, **Nous가 직접 만든 Hermes 4 모델은 Hermes Agent 안에서 쓰는 게 공식적으로 권장되지 않습니다.** Hermes 4는 채팅·추론에 튜닝된 모델이라 Hermes Agent가 요구하는 빠른 연속 tool-calling 루프에는 맞지 않기 때문입니다 — [[스캐폴드 효과 (에이전트-모델 궁합)|스캐폴드와 모델의 궁합]]이 이름의 일치와는 무관하다는 걸 보여주는 사례입니다.

대신 공식 가이드가 권하는 조합은 용도별로 갈립니다.

- **자체 서빙** — Qwen3.6-27B(24GB+ VRAM)
- **API** — Claude Sonnet 4
- **무료·최소 사양** — Hermes-3-Llama-3.2-3B(거의 모든 하드웨어에서 구동) 또는 Qwen2.5-Coder-7B-Instruct(무료 오픈웨이트 중 품질 우수)

## 외부 도구 호출 통제 — toolset 제거만으로는 부족

특정 도구(예: 웹 검색)를 아예 못 쓰게 막고 싶다면, `config.yaml`의 `toolsets:` 목록에서 `web`/`search`/`browser`를 빼거나 `hermes chat --toolsets "terminal,file"`처럼 지정하면 됩니다. 이러면 모델에게 그 도구의 정의 자체가 넘어가지 않아 "구조적으로 못 부르는" 상태가 되는데, 이건 프롬프트로 타이르는 것보다는 훨씬 견고합니다.

다만 이것만으로 완전한 [[폐쇄망]] 통제라고 보면 안 됩니다 — `terminal` 도구가 켜져 있으면 `curl`·`wget` 같은 셸 명령으로 같은 효과(외부 요청)를 낼 수 있는 우회로가 남아있고, 공식 문서에도 "air-gap 전용 모드"는 없습니다(SSRF 방지 기능은 반대 방향 — 외부에서 내부망 접근을 막는 것). 즉 toolset 제거는 [[가드레일]]에서 말하는 "여러 층 중 하나"로만 취급하고, 네트워크 레벨 방화벽·터미널 도구 deny 규칙과 반드시 함께 걸어야 합니다. "외부 검색은 절대 없어야 한다"처럼 허용 도구 집합을 처음부터 완전히 열거할 수 있는 요구사항이면, 오히려 [[에이전트 상태 관리 (LangGraph)|LangGraph]]로 직접 그래프를 짜서 그 도구 자체를 코드에 아예 안 넣는 쪽이 더 강한 보장을 줍니다.

## 폐쇄망 도입 시 고려할 점

기능이 많을수록 반입·보안 검토 범위가 넓어진다는 원칙([[함수 호출 (Tool Use)#보안 — 협상 불가능한 다섯 원칙|함수 호출의 보안 원칙]] 참고)이 Hermes에는 특히 중요합니다. 코딩 어시스턴트가 목적이라면 Profiles의 코딩 프로필과 Kanban 정도만 켜고, Cron·Voice·Gateway·GEPA 같은 기능은 실제 필요가 확인되기 전까지는 꺼둔 최소 구성으로 시작하는 게 안전합니다. Voice Mode를 쓴다면 faster-whisper 모델 파일도 다른 임베딩 모델([[BGE-M3]] 등)과 마찬가지로 사전 반입 대상에 포함해야 합니다.
