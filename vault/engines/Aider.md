# Aider

터미널에서만 동작하는 오픈소스 **git-native 페어프로그래밍 에이전트**입니다. [[Cline]]·[[Continue.dev]]가 IDE 확장으로 편집기 안에 자리 잡는다면, Aider는 애초에 에디터가 없어도(SSH 원격 서버, tmux 세션 등) 커맨드라인만으로 완결됩니다.

## git이 곧 승인 흐름

Cline이 diff를 보여주고 버튼으로 승인받는 UI를 갖췄다면, Aider는 **수정할 때마다 자동으로 git commit**을 만들고 커밋 메시지까지 생성합니다. 승인·되돌리기는 UI 버튼이 아니라 `git log`·`git revert` 같은 표준 git 명령으로 처리됩니다 — 별도의 승인 계층을 새로 배우는 대신, 이미 있는 버전 관리 워크플로우에 에이전트를 얹는 방식입니다.

## Architect/Editor 투 모델 모드

추론이 강한(비싼) 모델이 "무엇을 어떻게 고칠지" 계획만 세우고(Architect), 그 계획을 실제 diff로 바꾸는 건 더 저렴한 모델(Editor)이 맡는 2단계 구성을 지원합니다. 계획 단계는 정확도가, 편집 단계는 처리량이 중요하다는 관찰에서 나온 분업이며, 값비싼 모델 호출 횟수를 줄이면서도 품질을 유지하는 비용 최적화 패턴입니다.

## 모델 독립적

[[Cline]]과 마찬가지로 특정 벤더에 묶여 있지 않고, LiteLLM을 통해 OpenAI 호환 엔드포인트([[vLLM]]·[[Ollama]] 등)를 그대로 붙일 수 있습니다. 폐쇄망에서는 자체 서빙 모델을 [[LiteLLM]] 게이트웨이 뒤에 두고 Aider가 그 엔드포인트만 보게 하는 구성이 자연스럽습니다.

## Cline과의 실무적 차이

| | Aider | Cline |
|---|---|---|
| 실행 환경 | 터미널 전용(에디터 불필요) | VS Code 확장 |
| 승인 흐름 | git commit/revert로 처리 | 액션마다 승인받는 전용 UI |
| 원격/스크립트 친화성 | SSH·tmux·CI 파이프라인에 넣기 쉬움 | 로컬 VS Code 세션에 종속 |
| 적합한 워크플로우 | 반복적인 다중 파일 리팩터링, 배치성 작업 | 대화하며 지켜보는 대화형 코딩 |
