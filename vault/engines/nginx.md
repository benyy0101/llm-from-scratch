# nginx

오픈소스 웹서버 겸 리버스 프록시입니다. 저희 스택에서는 [[LiteLLM]] 앞을 지키는 표준 진입구 역할을 합니다.

- **표준 진입구** — Open WebUI·Continue.dev가 LiteLLM 포트(4000)에 직접 말을 걸지 않고, 모든 트래픽이 nginx를 거쳐가게 합니다. 내부 서비스 포트를 그대로 노출하지 않는 일반적인 관행입니다.
- **TLS(HTTPS) 종료** — 사용자 쪽과는 암호화 통신을 하고, 내부적으로는 평문 HTTP로 LiteLLM에 전달합니다. LDAP 로그인 정보가 오가는 구간이라 이 암호화가 중요합니다.
- **타임아웃 관리** — nginx의 기본 타임아웃(보통 60초)은 LLM 응답 시간보다 짧아서, `proxy_read_timeout`을 넉넉하게 늘려주지 않으면 응답이 끝나기 전에 연결이 끊깁니다.
- **스트리밍 버퍼링 해제** — nginx는 기본적으로 응답을 조금씩 모았다가 보내는 버퍼링 동작을 합니다. 이게 [[스트리밍 응답]]과 충돌해서 토큰이 매끄럽게 안 나오고 뭉텅이로 끊겨 나오는 문제를 만듭니다 — `proxy_buffering off`로 이 기본값을 꺼줘야 합니다.

이 중 마지막 항목(스트리밍 버퍼링)이 실무에서 가장 자주 걸리는 함정입니다. LiteLLM이나 vLLM 자체의 버그가 아니라, **표준 진입구로 nginx를 세우면서 딸려오는 기본 설정 충돌**이라는 걸 알아두면 원인 파악이 빨라집니다.
