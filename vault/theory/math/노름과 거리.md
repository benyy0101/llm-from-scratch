# 노름과 거리

벡터 사이의 거리는 전부 `d(a,b) = ||a-b||` 꼴이고, `||·||`(노름)을 뭘로 정의하느냐에 따라 완전히 다른 "가까움"이 됩니다. 점 A=(1,1), B=(4,5)를 예로 들면:

- **L1(맨해튼 거리)**: `|4-1|+|5-1| = 7` — 도시 격자에서 대각선으로 못 가고 블록을 따라 이동하는 거리
- **L2(유클리드 거리)**: `√(3²+4²) = 5.0` — 직선 거리, 우리가 보통 생각하는 "거리"
- **L∞(체비셰프 거리)**: `max(3,4) = 4` — 가장 크게 벌어진 축 하나만으로 결정

## 코사인 유사도 — 임베딩 검색이 실제로 쓰는 척도

`cos_sim(a,b) = (a·b) / (||a||·||b||)`, 범위는 -1~+1. [[벡터와 행렬|내적]]을 두 벡터 크기로 나눠서 **방향만** 비교하고 크기(길이)는 무시합니다. 이게 텍스트 임베딩에서 중요한 이유는, "고양이에 관한 문서"가 길든 짧든 단어 분포의 방향이 같으면 코사인 유사도가 1.0이 나오기 때문입니다 — 문서 길이는 노이즈고 방향이 의미라는 것. [[임베딩과 벡터DB|벡터DB]]가 검색에 내적 또는 코사인 유사도를 쓰는 이유가 여기 있고, 임베딩이 L2 정규화(길이를 1로 맞춤)돼 있으면 내적과 코사인은 완전히 같은 값이 됩니다.

## L1 vs L2 정규화 — 왜 하나는 희소해지고 하나는 안 그런가

손실 함수에 `||w||₁`을 더하면(라쏘) 일부 가중치가 정확히 0이 되는 희소한 해를 얻고, `||w||₂²`을 더하면(릿지) 가중치가 작아지긴 하지만 정확히 0이 되는 경우는 거의 없습니다. 기하학적으로 보면 이유가 명확합니다 — L1 제약 영역은 다이아몬드(모서리가 축 위에 있음)이고 L2 제약 영역은 원(부드러운 경계)입니다. 손실 함수의 등고선이 다이아몬드에 닿으면 보통 모서리(즉 어떤 축의 값이 0인 지점)에서 접하지만, 원에 닿으면 축 위가 아닌 부드러운 점에서 접합니다. 이게 [[베이즈 정리|MAP 추정]] 관점에서는 L1=라플라스 사전분포, L2=정규분포 사전분포에 대응됩니다.

## 언제 어떤 거리를 쓰는가

| 상황 | 최선의 선택 | 이유 |
|---|---|---|
| 텍스트/임베딩 유사도 | 코사인 | 크기는 노이즈, 방향이 신호 |
| 이미지 픽셀 비교 | L2 | 공간 관계, 비슷한 스케일 |
| 희소·고차원 특성 | L1 | 이상치 하나가 거리를 지배하지 않음 |
| 이상치 탐지 | 마할라노비스 | 특성 간 상관관계까지 고려한 거리 |
| 분포 비교 | [[정보이론\|KL divergence]] | 대칭은 아니지만 정보 손실량을 직접 측정 |

## 왜 중요한가

모든 손실 함수는 사실 "예측과 정답 사이의 거리"입니다 — MSE는 L2 제곱, MAE는 L1입니다. 그리고 모든 검색·추천·RAG 시스템은 어떤 거리 함수로 "가깝다"를 정의했느냐에 따라 완전히 다른 결과를 냅니다. 잘못된 거리를 고르면 모델이 최적화하는 대상 자체가 원하는 것과 어긋나버립니다.
