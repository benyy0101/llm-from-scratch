# 텐서 연산

텐서는 "숫자의 다차원 배열"입니다. 스칼라(rank 0), 벡터(rank 1), [[벡터와 행렬|행렬]](rank 2)을 넘어 그 이상의 차원도 다 텐서라고 부릅니다. LLM 서빙에서 실제로 마주치는 형태들:

- 이미지 배치: `(32, 3, 224, 224)` — 32장의 RGB 이미지, 각 224×224 픽셀
- 트랜스포머 입력: `(B, T, D)` = `(16, 128, 768)` — 배치 16, 시퀀스 길이 128, 임베딩 차원 768
- [[Multi-Head Attention|멀티헤드 어텐션]]: `(B, H, T, D)` = `(16, 12, 128, 64)` — 헤드 차원이 하나 더 늘어남

## 브로드캐스팅 — 형태가 다른 텐서를 어떻게 더하나

편향 벡터 `(3,)`를 행렬 `(2,3)`에 더할 때, 오른쪽부터 차원을 정렬해 크기가 같거나 1인 축을 자동으로 늘려서 맞춥니다. `(4,3) + (3,)` → `(4,3)`처럼 신경망의 모든 레이어가 사실 이 규칙 덕분에 "입력 + 편향"을 별도 코드 없이 처리합니다. PyTorch의 악명 높은 `shape mismatch` 에러가 대부분 이 정렬 규칙을 어겨서 생깁니다.

## Reshape·Transpose와 메모리 — "view"가 왜 가끔 실패하는가

텐서는 메모리에 1차원으로 쭉 저장돼 있고, `stride`(각 축을 한 칸 이동할 때 몇 칸을 건너뛰는지)가 이 1차원 데이터를 다차원처럼 보이게 해주는 메타데이터입니다. `transpose`는 데이터를 실제로 옮기지 않고 stride만 바꿔치기해서 "비연속(non-contiguous)" 상태를 만드는데, 이 상태에서 `reshape`을 시도하면 실패하는 경우가 있는 이유가 여기 있습니다(데이터를 실제로 복사해야 하는 `.contiguous()`가 필요해짐).

## Einsum — 멀티헤드 어텐션이 실제로 이렇게 짜여 있다

아인슈타인 합 표기법은 "입력에만 있는 축은 합산하고, 양쪽에 다 있는 축은 유지한다"는 규칙 하나로 내적·행렬곱·배치 연산을 통일해서 표현합니다.

| 연산 | einsum 패턴 |
|---|---|
| 내적 | `i,i->` |
| 행렬곱 | `ik,kj->ij` |
| 배치 행렬곱 | `bij,bjk->bik` |
| 어텐션 점수(QKᵀ) | `bhtd,bhsd->bhts` |
| 어텐션 출력(가중합) | `bhts,bhsd->bhtd` |

[[Query·Key·Value]]에서 설명한 "Query와 Key를 내적해 점수를 매기고, 그 점수로 Value를 가중합"하는 과정이 코드로는 정확히 이 두 einsum 줄로 구현됩니다 — 배치(b)와 헤드(h) 축은 그대로 유지한 채, 각자의 시퀀스 축(t, s)과 헤드 차원(d)에 대해서만 곱하고 합산하는 것입니다.

## 왜 중요한가

트랜스포머 코드는 수십 개의 reshape/transpose/permute가 연쇄적으로 이어져 있어서, 축 하나만 잘못 잡아도 형태 에러 없이 조용히 틀린 결과를 낼 수 있습니다(다른 축으로 브로드캐스트되거나 잘못 합산됨). 텐서의 rank·shape·stride 개념을 정확히 알고 있으면 이런 실수를 "형태를 보는 즉시" 잡아낼 수 있습니다.
