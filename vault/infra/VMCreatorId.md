# VMCreatorId

[[New-NetFirewallHyperVRule]]에 넘기는 파라미터로, "이 규칙을 어떤 종류의 [[가상머신]]에 적용할 것인가"를 지정합니다. 특정 VM 한 대의 ID가 아니라 **"이 VM을 만든 컴포넌트가 누구인가"**를 기준으로 삼는다는 점이 핵심입니다.

Hyper-V Manager로 직접 만든 VM, [[WSL2]]가 내부적으로 만드는 유틸리티 VM, Windows Sandbox가 만드는 VM 등은 각각 서로 다른 "생성 주체"이고, 마이크로소프트는 각 주체마다 고정된 [[GUID]]를 미리 배정해뒀습니다. [[WSL2]]의 값은 `{40E0AC32-46A5-438A-A0B2-2B479E8F2E90}`입니다.

이 방식이 필요한 이유는 WSL2의 유틸리티 VM이 **재부팅할 때마다 새로 생성**되기 때문입니다. VM 인스턴스 자체의 ID는 그때그때 바뀌지만, "이건 WSL이 만든 VM이다"라는 생성 주체 ID는 항상 고정이라서, VMCreatorId로 규칙을 걸어두면 재부팅 후에도 매번 다시 설정할 필요 없이 계속 적용됩니다.

## 관련
- [[New-NetFirewallHyperVRule]] — 이 값을 받는 cmdlet
- [[GUID]] — VMCreatorId 값의 형식과, 왜 고정값으로 미리 배정되는지에 대한 설명
- [[WSL2]] — 이 값이 실제로 가리키는 대상
- [[가상머신]] — "생성 주체별 고정 ID"가 필요한 이유(인스턴스 ID는 재부팅마다 바뀌기 때문)
