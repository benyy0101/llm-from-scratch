# 멀티턴과 멀티에이전트 (구분)

이름이 비슷해서 헷갈리지만 서로 다른 축의 개념입니다.

- **[[싱글턴과 멀티턴 (Tool Use)|멀티턴]]** — 에이전트 **한 명**이 대화를 여러 번 주고받으며, 그때그때 도구를 부를지 말지 재판단하는 것. "몇 번 말을 주고받나"의 축.
- **멀티에이전트** — 에이전트가 **여러 명** 동시에 존재하며 서로 협업하는 것. "몇 명이 일하나"의 축.

## 네 조합이 모두 가능하다

멀티턴 여부와 멀티에이전트 여부는 서로 독립된 축이라 다음처럼 조합됩니다.

| | 단일 에이전트 | 멀티에이전트 |
|---|---|---|
| **싱글턴** | 질문 하나에 도구 하나 부르고 끝 | 여러 에이전트가 각자 한 번씩만 일하고 결과를 합침 (예: [[함수 호출 (Tool Use)|클로드 코드]]의 서브에이전트를 병렬로 여러 개 띄워 각각 한 작업만 시키는 경우) |
| **멀티턴** | [[Cline]]처럼 한 에이전트가 여러 파일을 오가며 계획-실행-재판단을 반복 | [[Hermes Agent]]의 Bot Mode처럼 여러 에이전트가 계속 메시지를 주고받으며 협업 (제일 복잡) |

## 왜 구분이 중요한가

멀티에이전트를 쓰더라도 봇/서브에이전트 개개인은 여전히 각자 [[싱글턴과 멀티턴 (Tool Use)|멀티턴 판단]](도구를 부를지 말지, 언제 멈출지)을 해야 합니다. 즉 멀티에이전트는 "누가 일하는가"를 조율하는 상위 레이어(오케스트레이션)이고, 멀티턴은 그 안에서 개별 에이전트가 겪는 판단 난이도입니다. 두 문제는 겹쳐서 작동하지만 해결책은 다릅니다 — 멀티턴 약점은 모델의 [[함수 호출 (Tool Use)]] 정확도(→ [[Tool-Use 벤치마크 (BFCL)]])로 개선하고, 멀티에이전트 문제는 위임·라우팅·조율 로직으로 개선합니다.
