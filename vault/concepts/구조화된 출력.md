# 구조화된 출력

LLM은 본질적으로 문자열을 생성하는데, 애플리케이션은 대개 타입이 정해진 JSON을 필요로 합니다. "JSON으로 답해줘"라는 프롬프트만으로도 대략 90%는 맞게 나오지만, 나머지 10%가 문제입니다 — 마크다운 코드펜스로 감싸거나, 설명 문장을 앞에 붙이거나, 문법이 깨지거나, 값을 지어내는 식으로 실패하고, 이 10%가 프로덕션 파이프라인을 실제로 무너뜨립니다.

## 네 단계 스펙트럼

강제력이 약한 순서대로 네 단계가 있습니다.

1. **프롬프트 기반 (~90% 신뢰도)** — 강제 장치 없음. 모델이 대체로 따르지만 코드펜스·전문·잘림·구조 오류로 이따금 실패합니다.
2. **JSON 모드** — API가 문법적으로 유효한 JSON만 보장합니다(OpenAI `response_format: {type: "json_object"}`). 다만 기대한 스키마와 일치한다는 보장은 없어서, 키가 더 있거나 타입이 다르거나 필드가 빠질 수 있습니다.
3. **스키마 모드** — API가 JSON Schema 준수를 강제합니다(OpenAI `json_schema`, Anthropic의 tool use `input_schema`, Gemini `response_schema`). 키·타입·제약이 정확히 스펙대로 나옵니다.
4. **제약 디코딩(Constrained Decoding)** — 토큰 단위로 강제합니다. 매 생성 스텝마다 스키마에 맞지 않는 토큰의 확률을 0으로 마스킹해서, 애초에 스키마를 벗어난 토큰 자체를 뽑을 수 없게 만듭니다. 이론상 100% 준수를 달성합니다.

3·4단계의 차이가 헷갈릴 수 있는데, 3단계는 "스키마에 맞는 출력이 나오도록 유도"하는 수준이고 4단계는 "스키마에 안 맞는 토큰은 애초에 후보에서 제외"하는 수준입니다 — 후자가 훨씬 강한 보장이지만, 특정 위치에서 유효한 다음 토큰이 무엇인지(`{"price":` 다음엔 숫자·따옴표·`null`/`true`/`false`·마이너스 부호만 유효) 매 스텝 계산해야 해서 디코딩 구현이 훨씬 복잡합니다.

## JSON Schema — 출력 구조를 명시하는 계약서

프로퍼티마다 타입(string·number·boolean·integer·array·object)을 정의하고, 필수/선택 필드를 나누고, 제약(최소/최대값, enum, 배열 길이, 정규식 패턴)을 건 선언적 스펙입니다. 예를 들어 상품 스키마라면 `product`(문자열), `price`(0 이상 숫자), `in_stock`(불리언)은 필수로, `categories`(문자열 배열)는 선택으로 정의하는 식입니다.

Python에서는 Pydantic 클래스를 정의하면 JSON Schema가 자동 생성되는 패턴이 흔한데, 스키마를 손으로 안 써도 되고 런타임 검증까지 딸려 옵니다. Instructor 같은 라이브러리는 Pydantic 모델을 그대로 받아, 스키마 불일치가 나면 오류 내용을 모델에 다시 넣어 자동 재시도한 뒤 검증된 인스턴스를 반환합니다.

## 스키마를 줘도 여전히 실패하는 지점

스키마 모드가 구조는 보장해도 내용까지 보장하진 않습니다.

- **값 자체를 지어냄** — 구조는 스펙과 정확히 일치하는데 값이 틀림(예: 실제로 없는 가격을 지어냄). 스키마 검증기가 못 잡는 부류의 실패입니다 — 이건 [[환각]] 문제지 형식 문제가 아닙니다.
- **enum 혼동** — 허용된 값 집합에 없지만 의미상 맞는 값을 출력.
- **깊은 중첩** — 4단계 이상 중첩된 스키마부터 오류율이 눈에 띄게 오릅니다.
- **배열 길이 위반** — `minItems`/`maxItems`를 걸어도 넘거나 모자라게 생성.
- **선택 필드 생략** — `null`을 명시적으로 채우는 대신 필드 자체를 아예 빼먹음.

대응은 스키마 제약을 더 촘촘히 걸고, 의미상 선택적이어도 필드를 필수로 지정한 뒤 명시적 `null`을 강제하고, 중첩 깊이를 얕게 유지하는 쪽입니다.

## 구조화된 출력 vs 함수 호출 — 같은 메커니즘, 다른 목적

둘 다 JSON Schema라는 같은 도구를 쓰지만 역할이 다릅니다. 구조화된 출력은 **출력 그 자체가 최종 산출물**입니다(예: 문서에서 상품 정보 추출). [[함수 호출 (Tool Use)]]은 출력이 최종 산출물이 아니라 **"이 함수를 이 인자로 실행해달라"는 중간 요청**입니다 — 모델이 여러 함수 중 하나를 선택해야 하는 상황에 씁니다.
