# Pipeline Parallelism

모델이 GPU 하나에 안 들어갈 때 쓰는 병렬화 전략 중 하나. 레이어 묶음을 GPU별로 나눠 순차적으로 통과시킵니다. [[Tensor Parallelism]]보다 GPU 간 통신은 적지만, GPU들이 순서대로 기다리는 "파이프라인 버블"이 생기는 단점이 있습니다.

## 학습 시점의 파이프라인 버블은 추론과 성격이 다르다

추론(서빙)에서 파이프라인 버블은 "GPU 1이 레이어 1~20을 계산하는 동안 GPU 2는 아직 받을 게 없어 논다"는 정도의 단순한 이야기입니다. 학습에서는 여기에 **역전파**가 겹칩니다 — 배치 하나가 파이프라인 끝(마지막 GPU)까지 순전파를 마쳐야 역전파가 반대 방향으로 다시 흐르기 시작하는데, 그동안 앞쪽 GPU들은 자기 몫의 역전파를 받을 때까지 계속 놀아야 합니다.

이걸 줄이는 표준 기법이 **마이크로배치**입니다. 배치 하나를 통째로 흘리는 대신 작은 조각(마이크로배치) 여러 개로 잘라, GPU 1이 마이크로배치 2의 순전파를 계산하는 동안 GPU 2는 마이크로배치 1의 순전파를(또는 역전파를) 동시에 처리하게 만듭니다(1F1B 스케줄). 그래도 파이프라인이 "채워지고 비워지는" 앞뒤 구간은 버블로 남는데, 예를 들어 8단계 파이프라인은 대략 12% 안팎의 GPU 시간이 이 버블로 낭비된다고 보고됩니다. 마이크로배치 수를 늘릴수록 버블 비중은 줄지만, 그만큼 저장해둬야 할 중간 활성화 값이 늘어 메모리와 트레이드오프가 생깁니다.

**DeepSeek-V3가 쓴 DualPipe**는 이 버블을 정면으로 겨냥한 최신 스케줄로, 순전파·역전파를 양방향에서 동시에 흘려보내 버블을 거의 없앱니다 — 자세한 메커니즘은 [[DualPipe 병렬화]] 참고.

**요점**: 추론의 파이프라인 버블은 "배치가 작아서 생기는 낭비"에 가깝고, 학습의 파이프라인 버블은 "순전파 전체가 끝나야 역전파가 시작될 수 있다"는 구조적 제약에서 나옵니다 — 그래서 학습용 파이프라인 병렬화는 마이크로배치 스케줄링이라는 별도의 설계가 필요합니다.
