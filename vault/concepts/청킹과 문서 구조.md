# 청킹과 문서 구조

[[청킹]]에서 다룬 "왜 자르는가·문장 경계·overlap" 기초를 넘어, 청크 크기가 만드는 트레이드오프와 표·제목 같은 문서 구조를 어떻게 보존할지를 다룹니다. 청크 크기는 검색의 세밀함과 문맥 보존 사이의 선택입니다.

## 크기에 따른 차이

- **작은 청크** — 관련 구절을 좁혀 찾기 좋지만 조건·예외·제목이 분리될 수 있습니다.
- **큰 청크** — 문맥을 보존하지만 여러 주제가 섞이고 입력 길이가 늘어납니다.
- **Overlap** — 경계 문장을 겹쳐 문맥 단절을 줄이지만 결과 중복이 늘어납니다.

‘보증기간 1년. 다만 침수는 제외’에서 두 번째 문장만 떨어지면 무엇에서 제외하는지 불완전해집니다. 문장 경계만 지켰다고 의미 단위까지 보존되는 것은 아닙니다.

## 구조 보존

- 표는 열 이름·행의 대상·값을 함께 보존합니다.
- 청크에 문서 ID·제목·원문 위치·개정일을 연결합니다.
- 글자 수와 [[토큰]] 수를 구분하고, 실제 모델에서 잘리는 위치를 확인합니다.

## Parent-child 방식

**작은 청크로 검색하고, 연결된 상위 문단을 가져와 읽히는 방식**입니다. 검색 단위와 답변 문맥의 크기를 분리합니다. 상위 문단 ID가 필요하고, 복원한 문맥도 입력 예산 안에 들어와야 합니다.
