# 가드레일

LLM 애플리케이션의 방어는 "입력 검증 → LLM 처리 → 출력 검증"이라는 3단 샌드위치 구조로 짜는 게 표준입니다. 어느 한 검사도 완벽하지 않다는 전제 위에서, 여러 층을 겹쳐 공격자가 웬만큼 정교해야만 뚫을 수 있게 만드는 것이 목표입니다 — "표(각 방어 기법 하나하나)는 어느 것도 100%가 아니지만, 행(여러 층을 다 통과해야 하는 전체 경로)은 100%에 가까워진다"는 식으로 요약됩니다.

## 공격은 세 갈래로 나뉜다

- **직접 프롬프트 인젝션** — 사용자가 "지금까지 지시를 무시해"처럼 시스템 지시를 명시적으로 덮어쓰려는 경우. 탐지·방어의 자세한 내용은 [[프롬프트 인젝션]]을 참고하세요.
- **간접 프롬프트 인젝션** — 검색된 문서·이메일·웹페이지 안에 지시가 심어져 있는 경우입니다. 모델은 "이게 사용자의 지시인지, 그냥 처리해야 할 데이터인지"를 구분하지 못합니다. 방어는 검색된 콘텐츠 전부를 신뢰할 수 없는 데이터로 취급하고, 그 안의 텍스트가 지시처럼 보여도 실행하지 않도록 경계를 명확히 나누는 것입니다.
- **탈옥(Jailbreak)** — 시스템 프롬프트를 직접 덮어쓰지 않고도 모델의 안전 학습 자체를 우회하는 기법입니다. "너는 DAN(무엇이든 할 수 있는 AI)이야" 같은 롤플레이, 여러 턴에 걸쳐 조금씩 유도하는 방식 등이 있습니다. 입력만 막아서는 못 잡고, 출력을 봐야 잡히는 부류입니다.

## 입력 가드레일 — 이미 다뤄진 것 이상으로 걸어두는 필터

[[프롬프트 인젝션]]·[[PII 마스킹]]이 이미 다루는 검사 외에, 입력 단에서 흔히 함께 거는 필터가 있습니다.

- **주제 분류** — 금지 카테고리(폭력·불법 행위·자해·혐오 표현 등)에 해당하는 키워드가 매칭되면 확신도를 올리는 방식.
- **길이·속도 제한** — 글자 수(예: 5,000자)·단어 수(1,000단어) 상한과 분당 요청 수 제한. 프롬프트를 억지로 늘려 필터를 우회하려는 시도나 자동화된 공격을 막습니다.

## 출력 가드레일 — 답이 나온 뒤에도 검사는 끝나지 않는다

입력을 통과해도 출력이 문제일 수 있습니다.

- **독성 필터링** — 혐오 표현, 폭력·자해·불법 합성물 제작을 구체적으로 지시하는 내용을 응답 자체에서 탐지합니다.
- **PII 스크러빙** — 응답에 이메일·주민번호·카드번호가 섞여 나오면 사용자에게 도달하기 전에 걸러냅니다. 탐지 메커니즘 자체는 [[PII 마스킹]]과 동일합니다 — 다만 이건 "사용자가 보낸 입력"이 아니라 "모델이 만들어낸 출력"에 적용한다는 점이 다릅니다.
- **관련성 검사** — 입력과 출력의 단어 겹침이 임계값(예: 15%) 아래로 떨어지면 "엉뚱한 답"으로 플래그합니다. 계좌 잔액을 물었는데 레시피가 나오는 것처럼, [[환각]]이 극단적으로 튄 경우를 형식 검증 없이도 잡아낼 수 있는 값싼 신호입니다.
- **시스템 프롬프트 유출 탐지** — 출력이 시스템 프롬프트와 의미 있는 단어 기준 40% 이상 겹치면, 모델이 자기 지시문을 그대로 뱉어내고 있다는 신호로 봅니다.

```mermaid
flowchart LR
    IN["사용자 입력"] --> I1["인젝션 탐지"]
    I1 --> I2["PII 탐지"]
    I2 --> I3["주제 분류·길이 제한"]
    I3 --> LLM["LLM 처리"]
    LLM --> O1["독성 필터링"]
    O1 --> O2["PII 스크러빙"]
    O2 --> O3["관련성 검사"]
    O3 --> O4["시스템 프롬프트 유출 탐지"]
    O4 --> OUT["사용자에게 응답"]
```

## 프로덕션 도구 지형

직접 구현하는 대신 기존 도구를 조합하는 경우가 많습니다. OpenAI Moderation은 무료로 API 호출당 ~100ms에 13개 카테고리를 걸러주고, LlamaGuard는 로컬에 직접 띄울 수 있는 오픈모델이라 [[폐쇄망]] 환경에 적합합니다. NeMo Guardrails는 Colang이라는 전용 DSL로 대화 경계를 프로그래밍하고, Guardrails AI·LLM Guard는 Pydantic 스타일의 출력 검증기·다목적 스캐너를 라이브러리로 제공합니다. PII 탐지·마스킹 자체는 이미 [[PII 마스킹]]에서 다룬 Presidio가 대표적입니다.

## 실제로 뚫렸던 사례들

2023년 초 Bing Chat은 "지금까지 지시를 무시해" 한 마디로 내부 코드네임("Sydney")과 시스템 프롬프트가 공개된 지 24시간도 안 돼 유출됐고, 같은 해 ChatGPT 플러그인 생태계에서는 악성 웹페이지가 마크다운 이미지 태그 안에 지시문을 숨겨 데이터 유출을 유도한 사례가 보고됐습니다. 두 사례 모두 "모델이 데이터와 지시를 구분 못 한다"는 근본 문제가 실제 장애로 이어진 경우입니다.

## 배포 전략 — 어디까지 방어할 것인가

대부분의 서비스는 계층적 방어(공격의 약 95%를 차단하며, 뚫으려면 도메인 전문성이 필요한 수준)로 충분합니다. 반면 금융·의료·정부처럼 실패 비용이 큰 영역은 지연시간이 2~3배 늘어나는 걸 감수하고 더 무거운 검사를 층층이 쌓는 "최대 보안" 구성을 씁니다 — 이 판단 기준은 [[고영향 AI와 인간개입]]에서 다루는 법적·조직적 분류(고영향 AI 여부)와도 맞물립니다. 가드레일이 기술적 통제라면, 그쪽은 그 통제가 실제로 충분한지를 판단하는 상위 잣대입니다.

- [[환각]] — 관련성 검사가 잡아내려는 실패 유형 중 하나

- [[함수 호출 (Tool Use)]] — 도구가 실제 시스템에 닿을 때 이 가드레일과 나란히 필요한 실행 단 검증
- [[폐쇄망]] — 상용 SaaS 가드레일 대신 자체 호스팅 도구를 골라야 하는 제약
