# RAG 평가

**검색 → 정렬 → 실제 입력 → 답변**을 나눠 측정하는 작업입니다. 최종 답이 틀렸다는 사실만으로 어느 단계를 고칠지 알 수 없기 때문입니다.

## 실패 지점

| 관찰 | 먼저 확인할 대상 |
|---|---|
| 원문 조항이 색인에 없음 | 추출·청킹·문서 갱신 |
| 색인에 있지만 후보에 없음 | 검색 방식·질의·필터 |
| 후보에 있지만 최종 k개에 없음 | 리랭킹 |
| 선택됐지만 실제 입력에서 잘림 | 컨텍스트 구성 |
| 입력에 있는데 잘못 답함 | 생성·프롬프트 |

## 검색 지표

- **Recall@N** — 관련 근거가 후보에 얼마나 포함됐는가
- **Precision@k** — 최종 k개 중 관련 결과의 비율
- **MRR@k** — 첫 관련 결과 순위의 역수 평균. k 안에 없으면 0
- **nDCG@k** — 관련성이 높은 결과를 위에 배치했는가

MRR은 1위면 1, 2위면 1/2입니다. 첫 근거만 보므로 여러 필수 근거의 누락을 설명하기 어렵습니다.

nDCG는 관련성 등급 rel의 이득을 순위에 따라 할인하고, 이상적 순서의 IDCG로 나눕니다. 다음은 gain을 2^rel−1로 둔 정의입니다.

$$DCG@k=\sum_{i=1}^{k}\frac{2^{rel_i}-1}{\log_2(i+1)}, \qquad nDCG@k=\frac{DCG@k}{IDCG@k}$$

관련성 등급·gain 정의·정답 없는 질문 처리 방식을 고정해야 비교할 수 있습니다.

## 비교 실험

1. 질문·원문 근거·문서 버전을 고정하고 튜닝용/평가용 질문을 나눕니다.
2. 동일 후보 수로 dense·BM25·하이브리드를 비교합니다.
3. **같은 후보**에 리랭킹을 적용해 정렬 효과를 분리합니다.
4. 생성 모델·프롬프트·입력 예산을 고정해 답변을 비교합니다.
5. 품질과 함께 p50·p95 지연, 토큰 길이, 동시 요청 조건을 기록합니다.

위 순서는 실험 설계이며 이 저장소의 실측 결과는 아닙니다.

## 답변 평가

정확성, 근거에 대한 충실성, 인용의 타당성, 답이 없을 때의 보류를 따로 봅니다. 자동 판정도 사람이 검토한 기준과 대조합니다.
