# MCP (Model Context Protocol)

[[함수 호출 (Tool Use)]]을 여러 애플리케이션이 쓰다 보면 같은 도구(예: 사내 위키 검색)를 Claude Code용, Cursor용, 사내 챗봇용으로 각각 다시 구현하게 됩니다. MCP는 이 중복을 없애기 위한 Anthropic 공개 표준으로, "AI 애플리케이션이 도구·리소스·프롬프트를 발견하고 호출하는 방법"을 JSON-RPC 기반의 공통 프로토콜 하나로 통일합니다. "도구 네트워킹계의 HTTP"에 비유되는 이유가 여기 있습니다 — 서버 하나만 MCP로 구현해두면, 그 프로토콜을 말할 수 있는 어떤 클라이언트든 별도 통합 코드 없이 그 서버의 기능을 그대로 씁니다.

## 네 가지 역할

- **Host** — 모델·UI·의사결정을 소유한 AI 애플리케이션 자체(예: Claude Code)
- **Client** — 서버 하나와 MCP로 통신하는 주체(Host 내부에 있음)
- **Server** — 도구·리소스·프롬프트를 공개하는 쪽(예: 사내 위키 검색 서버)
- **Transport** — 이 둘 사이에서 JSON-RPC 메시지를 실어 나르는 통로(stdio 또는 HTTP)

## 서버가 공개하는 세 가지

1. **Tools** — 이름·설명·JSON Schema 입력 스펙을 가진 호출 가능한 액션. [[함수 호출 (Tool Use)]]에서 다룬 도구 정의와 개념적으로 같습니다.
2. **Resources** — URI로 주소가 붙은, 클라이언트가 읽을 수 있는 콘텐츠(파일, DB 레코드 등).
3. **Prompts** — 사용자나 모델에게 노출할 재사용 가능한 프롬프트 템플릿.

## 왜 굳이 프로토콜을 표준화하는가

MCP가 없으면 도구 하나를 붙일 때마다 그 애플리케이션의 API 형식에 맞춰 새로 통합해야 합니다. MCP 서버로 한 번만 감싸두면, 이 프로토콜을 지원하는 모든 호스트(Claude Code, Cursor, 커스텀 에이전트 등)가 같은 서버를 그대로 재사용할 수 있어 "N개 애플리케이션 × M개 도구"만큼 필요했던 통합 작업이 "M개 서버"로 줄어듭니다.

이 노트는 개괄만 다룹니다 — MCP 자체는 프로토콜 세부사항(전송 계층, 오류 코드, 상태 관리 방식 등)만으로도 별도의 전문 커리큘럼이 필요할 만큼 깊은 주제입니다.

## 관련
- [[함수 호출 (Tool Use)]] — MCP가 표준화하는 "도구 정의·호출"의 원형 개념

- [[ACP (Agent Client Protocol)]] — 방향이 다른 자매 프로토콜(에이전트-도구가 아니라 에이전트-에디터를 표준화)
