# GPT와 인과적 언어모델링

인과적 언어모델링(Causal Language Modeling)이 푸는 문제는 딱 하나입니다 — "앞의 토큰 t-1개가 주어졌을 때, t번째 토큰은 무엇일 확률이 가장 높은가?"(`P(x_t | x_<t)`). GPT는 [[Transformer]]의 디코더만 쌓아서 이 질문 하나를 반복해서 풀도록 만든 구조입니다. [[BERT와 MLM|BERT]]가 `P(x_masked | x_unmasked)`처럼 양쪽을 다 보고 빈칸을 채우는 것과 정확히 대비됩니다 — 이 차이 때문에 BERT는 생성을 못 하고 GPT는 생성을 할 수 있습니다.

## 삼각형 하나로 이해하는 인과 마스크

[[Causal Masking]]이 왜 필요한지는 그 노트에서 다루지만, 이 마스크가 등장한 과정을 단계별로 보면 "왜 하필 이런 모양인가"가 자연스럽게 풀립니다.

1. **1단계 — 접두사 평균**: 위치 i의 출력 = 위치 0~i까지의 단순 평균. 이걸 행렬로 쓰면 하삼각(lower-triangular) 행렬이 됩니다.
2. **2단계 — 학습된 가중치**: 평균을 균등 가중치 대신 학습 가능한 점수 S로 바꿉니다. 미래 위치는 `-∞`로 채우고 softmax를 적용하면(`exp(-∞)=0`이라 가중치가 정확히 0이 됨), 여전히 과거만 보는 가중합입니다.
3. **3단계 — 내용 기반 가중치**: 점수 S를 고정값이 아니라 `S = QKᵀ/√d_k`로, 즉 지금 토큰과 과거 토큰 내용에 따라 매번 다시 계산합니다. 이게 바로 [[Query·Key·Value|어텐션]]입니다. 마스킹과 softmax 방식은 1단계 이후로 하나도 안 바뀌었습니다.

즉 인과 마스크는 어텐션을 위해 나중에 갖다 붙인 트릭이 아니라, "과거만 평균 낸다"는 가장 단순한 아이디어가 학습 가능한 가중치로, 다시 내용 기반 가중치로 자연스럽게 진화한 결과물입니다.

## 학습은 병렬, 추론은 직렬 — 두 세계가 다르다

**학습 시**: 길이 N짜리 시퀀스 하나를 통째로 한 번의 순전파에 넣으면, 인과 마스크 덕분에 N개 위치 전부에서 동시에 "다음 토큰 맞히기" 손실을 계산할 수 있습니다. 입력 `[t1,t2,t3]`과 목표 `[t2,t3,t4]`를 나란히 놓고 위치별 `-log P(target_i | inputs_{≤i})`를 전부 더하는 방식입니다. 100만 토큰짜리 시퀀스도 GPU 한 번의 패스로 처리됩니다.

**추론 시**: 토큰을 하나 만들면 그걸 다시 입력에 이어붙여 다음 토큰을 만드는 과정을 반복해야 합니다 — `[t1,t2,t3] → t4`, `[t1,t2,t3,t4] → t5` … 이 순차성을 흔히 "자기회귀 세금(autoregressive tax)"이라고 부릅니다. 매 스텝 과거 토큰의 Key·Value를 다시 계산하지 않도록 캐시해두는 장치가 바로 [[KV 캐시]]이고, 이 캐시가 안전하게 재사용될 수 있다고 수학적으로 보장해주는 게 바로 이 노트에서 다룬 인과 마스크입니다.

## GPT-2 이후 아키텍처는 거의 그대로다

GPT-1(2018)부터 최근 모델까지 핵심 루프 자체는 크게 바뀌지 않았습니다. 실제로 성능을 끌어올린 건 아키텍처 변경이 아니라 다음 세 가지였습니다.

1. **스케일** — 파라미터와 학습 토큰 수를 계속 키움 (자세한 산식은 [[스케일링 법칙]])
2. **문맥 내 학습(In-context learning)** — 별도 재학습 없이 프롬프트만으로 작업을 수행하는 능력이 대략 수십억 파라미터 규모부터 나타남
3. **후처리(post-training)** — SFT·RLHF·DPO 등으로 원본 사전학습 모델을 사람이 쓰기 좋은 형태로 다듬는 단계

구조적으로 달라진 부분은 대개 세부 최적화입니다 — LayerNorm을 서브레이어 앞으로 옮긴 Pre-norm, [[위치 인코딩|RoPE]], SwiGLU 활성화 등이 조합돼 더 큰 규모에서도 학습이 안정적으로 되도록 만들었을 뿐, "다음 토큰을 예측한다"는 근본 루프는 그대로입니다.

## 디코딩 전략 한눈에

토큰 하나를 확률분포에서 실제로 어떻게 뽑아낼지는 별도의 선택지입니다.

| 전략 | 용도 |
|---|---|
| Greedy(최댓값 선택) | 코드 완성처럼 결정적 출력이 필요할 때 |
| Temperature | 확률분포를 뾰족하게/평평하게 조절, 창의적 출력 |
| Top-p(nucleus) | 누적확률이 p 이상이 되는 최소 후보군만 남김 |
| [[Speculative Decoding]] | 작은 모델이 여러 토큰을 미리 제안, 큰 모델이 한 번에 검증 |
