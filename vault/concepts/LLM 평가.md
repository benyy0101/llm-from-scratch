# LLM 평가

[[모델 평가]]에서 다룬 정밀도·재현율·F1은 "정답이 명확한 분류/회귀 문제"를 잰다는 전제가 깔려 있습니다. LLM은 출력이 자유 형식 텍스트라 "정답과 얼마나 같은가"를 그 틀로 바로 잴 수 없는 경우가 많습니다. LLM 평가는 이 문제를 몇 가지 서로 다른 각도에서 우회하는 방법들의 모음입니다 — 어느 하나도 완벽하지 않아서, 실무에서는 여러 방법을 겹쳐 씁니다.

## Perplexity — "다음 토큰을 얼마나 헷갈려하는가"

```
PPL = exp( -1/N · Σ log P(정답 토큰) )
```

모델이 정답 토큰에 매긴 확률의 평균을 지수로 되돌린 값으로, 낮을수록 모델이 다음 토큰을 자신 있게 맞춘다는 뜻입니다(GPT-2 약 30, Llama 3 8B 약 7). [[사전학습(Pretraining)]]의 손실 함수(교차 엔트로피)를 그대로 지수 변환한 값이라 계산이 쉽고 사람 라벨이 필요 없다는 장점이 있지만, "자주 나오는 패턴을 잘 맞히는가"만 잴 뿐 지시 이행·추론·사실 정확성은 전혀 반영하지 못합니다 — 사전학습 중간 점검용으로는 유용해도, 이걸로 "이 모델이 쓸만한가"를 판단할 수는 없습니다.

## 벤치마크 — MMLU·HumanEval류

57개 과목 15,908문제로 구성된 MMLU(다지선다 지식 평가), 164개 문제로 코드 생성 능력을 재는 HumanEval처럼, 정답이 정해진 표준화된 문제 세트로 점수를 매기는 방식입니다. GPT-4·Claude 3 Opus·Llama 3 405B가 MMLU에서 모두 86~89% 사이에 몰려있는 것처럼, 최상위권 모델 간 점수 차이가 2~3점 안으로 좁혀지면 그 차이는 통계적 잡음과 구분하기 어려워집니다. 더 근본적인 문제는 굿하트의 법칙("측정 지표가 목표가 되는 순간 그 지표는 좋은 측정 수단이길 멈춘다")입니다 — 벤치마크 문제(나 비슷한 문제)가 학습 데이터에 섞여 들어가면, 점수는 오르지만 실제 능력이 는 것인지 벤치마크를 외운 것인지 구분할 수 없게 됩니다.

## LLM-as-Judge — 채점을 다른 LLM에게 맡기기

자유 형식 응답을 사람이 일일이 채점하는 대신, 더 강한 모델(GPT-4o, Claude 등)에게 "이 응답을 1~5점으로 평가하라"는 프롬프트를 주고 채점을 맡기는 방식입니다. 사람 평가와 약 80% 일치하고 판정당 비용이 매우 낮아(예: $0.01 안팎) 대량 평가에 실용적이지만, 몇 가지 체계적 편향이 보고됩니다 — 먼저 제시된 응답을 더 선호하는 위치 편향, 짧은 것보다 긴 응답을 후하게 채점하는 길이 편향, 그리고 GPT-4가 GPT-4의 산출물을 더 후하게 평가하는 자기 선호 편향입니다.

## 사람 평가와 Elo 랭킹

같은 질문에 대해 모델 두 개의 답을 나란히 보여주고 사람이 더 나은 쪽을 고르게 한 뒤, 체스 랭킹과 같은 원리(Elo)로 상대적 순위를 매기는 방식입니다. Chatbot Arena가 이런 방식으로 수백만 건의 투표를 모아 모델 순위를 매기고 있으며, "이 응답이 몇 점인가"라는 절대 평가보다 "이 두 응답 중 어느 게 나은가"라는 상대 비교가 사람에게 훨씬 신뢰성 있는 판단이라는 게 이 방식의 근거입니다. 다만 판정당 비용이 LLM-as-Judge보다 훨씬 높습니다($0.10~$2.00 수준).

## 결국 중요한 건 맞춤형 평가

벤치마크·LLM-as-Judge·Elo 랭킹 모두 "이 모델이 일반적으로 얼마나 잘하는가"를 재는 도구일 뿐, 실제 배포 환경(내 서비스의 프롬프트 분포, 내 데이터)에서 얼마나 잘 작동할지는 별도로 재야 합니다. 자신의 과제에 맞춰 직접 구성한 테스트 세트(운영 단계 기준 200개 이상 권장)에 Exact Match·F1·LLM-as-judge 등을 적용하는 "맞춤형 평가"가 실무에서 가장 신뢰할 수 있는 신호로 꼽힙니다.

## RAG·환각·가드레일과의 연결 — 이미 다뤄진 것과의 관계

[[RAG]]의 검색 단계나 [[환각]] 탐지, 가드레일의 허용/차단 판정은 사실 전부 이진 분류 문제라서 [[모델 평가]]의 정밀도·재현율 틀을 그대로 재사용할 수 있습니다. 이 노트에서 다루는 perplexity·벤치마크·LLM-as-Judge·Elo는 그와 달리 "정답이 하나로 고정되지 않는 자유 형식 생성"을 재는 방법이라는 점에서 역할이 나뉩니다 — 판정 대상이 이진 분류로 환원되면 [[모델 평가]] 쪽을, 자유 형식 생성 품질 자체를 재려면 이 노트의 방법들을 씁니다.
