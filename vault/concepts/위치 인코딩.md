# 위치 인코딩

`Attention(Q,K,V) = softmax(QKᵀ/√d_k)·V` 계산은 토큰 사이의 **순서를 전혀 모릅니다**. 내적과 가중합만 하는 연산이라, "고양이가 매트에 앉았다"와 그 단어를 뒤죽박죽 섞은 문장을 [[Query·Key·Value]] 입장에서는 구별할 방법이 없습니다 — 집합을 다루는 연산이지 수열을 다루는 연산이 아니기 때문입니다. 그래서 토큰 임베딩과는 별도로 "이 토큰이 몇 번째 위치인가"라는 정보를 어떻게든 끼워 넣어야 하고, 이 문제를 푸는 세 가지 방식이 있습니다.

## 1. 절대 사인파 인코딩 (원조 Transformer, 2017)

```
PE[pos, 2i]   = sin(pos / 10000^(2i/d_model))
PE[pos, 2i+1] = cos(pos / 10000^(2i/d_model))
```

각 임베딩 차원마다 주파수가 다른 사인파 하나씩을 대응시켜서, 위치 `pos`마다 고유한 파형 패턴이 생기게 만드는 방식입니다. 이 값을 토큰 임베딩에 그냥 더합니다. 학습이 전혀 필요 없고 구현도 단순하지만, 학습 때 본 적 없는 길이(예: 2048까지 학습했는데 4096 위치가 들어옴)에서는 파형 패턴이 낯선 값이 되어 성능이 무너집니다 — **외삽(extrapolation)에 약하다**는 게 핵심 약점입니다.

## 2. RoPE — 회전으로 상대 거리를 인코딩 (2021)

RoPE(Rotary Position Embedding)는 값을 더하는 대신, Query·Key 벡터를 **위치에 비례하는 각도만큼 회전**시킵니다. 2차원 한 쌍 `(x_2i, x_2i+1)`에 대해:

```
x'_2i   = x_2i · cos(pos·θᵢ) − x_2i+1 · sin(pos·θᵢ)
x'_2i+1 = x_2i · sin(pos·θᵢ) + x_2i+1 · cos(pos·θᵢ)     (θᵢ = 10000^(−2i/d_head))
```

이 트릭의 진짜 가치는 계산 결과에 있습니다. Query를 위치 m에서, Key를 위치 n에서 각각 회전시킨 뒤 내적을 하면, 결과가 m과 n 각각의 값이 아니라 **(m−n)이라는 상대 거리만의 함수**가 됩니다 — 회전이라는 연산의 성질(각도 차이만 남고 절대 각도는 사라짐) 덕분입니다. 절대 위치를 이용해 계산했는데 어텐션이 실제로 인식하는 건 상대 거리뿐이라는 점이 핵심입니다. 그래서 학습 때 없던 긴 위치가 나와도 "얼마나 멀리 떨어져 있는가"라는 상대적 관계는 여전히 의미가 있어, 사인파 방식보다 외삽에 훨씬 강합니다. 여기에 `θ`를 계산하는 기준값(base, 기본 10000)을 조정하거나 위치를 재스케일링하는 방식(NTK-aware, YaRN 등)을 더하면 학습 길이의 수십 배까지 컨텍스트를 늘릴 수 있습니다. Llama, Qwen, Mistral, DeepSeek-V3 등 현재 주요 오픈 모델이 대부분 RoPE를 표준으로 채택하고 있습니다.

## 3. ALiBi — 아예 위치를 어텐션 점수에 직접 벌점으로

```
attn_score[i,j] = (qᵢ·kⱼ)/√d − m_h · |i−j|
```

임베딩을 건드리지 않고, 어텐션 점수 자체에 "멀리 있는 토큰일수록 점수를 깎는" 선형 벌점을 더합니다. `m_h`는 헤드마다 다른 기울기 값입니다. 추가 학습이 필요 없고 외삽 성능이 뛰어나지만, 상대 거리만 표현할 수 있어 표현력이 RoPE보다 단순합니다(BLOOM, MPT 등에서 채택).

## 비교

| 방식 | 외삽 성능 | 학습 비용 | 채택 사례 |
|---|---|---|---|
| 절대 사인파 | 약함 | 없음 | 초기 Transformer, BERT |
| RoPE | 좋음(스케일링 기법과 결합 시 강함) | 없음 | Llama, Qwen, Mistral, DeepSeek-V3 |
| ALiBi | 우수 | 없음 | BLOOM, MPT |

RoPE가 사실상 표준으로 자리 잡은 이유는, 구조 변경 없이 `θ`의 기준값 하나만 조정해도 [[컨텍스트 윈도우]]를 늘리는 다양한 기법(YaRN, NTK-aware 등)을 그대로 얹을 수 있는 확장성 때문입니다.
