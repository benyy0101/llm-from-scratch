# Tensor Parallelism

모델이 GPU 하나에 안 들어갈 때 쓰는 병렬화 전략 중 하나. 레이어 하나의 행렬 연산 자체를 여러 GPU에 쪼갭니다. GPU 간 통신이 잦아서 NVLink처럼 빠른 인터커넥트가 필요합니다. [[Pipeline Parallelism]]과 섞어서 70B급 이상 모델을 서빙할 때 흔히 함께 씁니다.

## 학습 시점에는 왜 이것만으로 부족한가

지금까지 다룬 건 추론(서빙) 관점입니다 — 가중치만 GPU에 올리면 되는 상황이라 "모델이 GPU 하나에 안 들어간다"는 문제가 비교적 단순합니다. 학습 시점은 사정이 다릅니다. 70B 모델을 예로 들면:

| 항목 | 용량 | 비고 |
|---|---|---|
| 가중치(FP16) | 140GB | 추론과 동일 |
| 그래디언트 | 140GB | [[역전파]] 결과, 추론엔 없음 |
| Adam 옵티마이저 상태 | 560GB | 파라미터마다 FP32로 1차·2차 모멘트 저장 |
| **합계** | **840GB** | 활성화 값은 별도 |

가중치만 놓고 보면 추론의 6~8배에 달하는 메모리가 필요합니다 — Adam이 파라미터마다 평균과 분산을 FP32로 따로 들고 있는 옵티마이저 상태가 가장 큰 비중을 차지합니다. 이 문제를 Tensor/Pipeline Parallelism과는 다른 축에서 푸는 게 **데이터 병렬화(Data Parallelism)**와 **ZeRO**입니다.

- **데이터 병렬화** — 모델 전체를 GPU마다 통째로 복제하고, 배치만 나눠서 각자 순전파·역전파를 돌린 뒤 그래디언트를 all-reduce로 평균 냅니다. 처리량은 GPU 수만큼 선형으로 늘지만, GPU 한 대가 감당해야 하는 메모리(840GB)는 전혀 줄지 않습니다 — Tensor/Pipeline Parallelism이 "한 모델을 쪼개 나눠 담는" 문제를 풀었다면, 데이터 병렬화는 애초에 그 문제를 안 풀고 처리량만 늘리는 별개의 축입니다.
- **ZeRO** — 데이터 병렬화의 "모델을 통째로 복제한다"는 전제 자체를 깨고, 옵티마이저 상태·그래디언트·파라미터를 GPU 수만큼 나눠 담습니다. ZeRO-1(옵티마이저 상태만 샤딩)은 약 4배, ZeRO-2(+그래디언트)는 약 8배, ZeRO-3(+파라미터까지)은 GPU 수에 거의 비례해 메모리를 줄입니다. 70B 모델을 8-GPU로 ZeRO-3까지 적용해도 GPU당 약 105GB가 필요해 80GB급 카드로는 여전히 부족하고, 실제로는 16GPU 이상으로 굴려야 합니다.

**요점** — 추론에서 "모델을 어떻게 쪼갤까"는 오직 가중치 크기의 문제지만, 학습에서는 가중치·그래디언트·옵티마이저 상태를 동시에 감당해야 해서 Tensor/Pipeline Parallelism(모델을 쪼개는 축)과 데이터 병렬화·ZeRO(같은 모델 여러 벌을 돌리며 그 여러 벌 사이에서 메모리를 다시 나누는 축)를 겹쳐 써야 합니다. 실전 대규모 학습(GPT-3, Llama 계열 등)은 이 네 가지를 동시에 조합하는 3D/4D 병렬화로 돌아갑니다.
