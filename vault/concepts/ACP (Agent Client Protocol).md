# ACP (Agent Client Protocol)

에이전트가 **어떤 에디터에서든** 채팅·파일 diff·터미널 실행·승인 흐름을 동일하게 제공할 수 있게 해주는 프로토콜입니다. [[Hermes Agent]]가 VSCode·Zed·JetBrains를 동시에 지원하는 이유가 이 프로토콜 덕분입니다.

## MCP와 헷갈리기 쉽지만 방향이 다름

- **[[MCP (Model Context Protocol)|MCP]]** — 에이전트가 **도구·데이터소스**에 접근하는 방식을 표준화 (에이전트 → 외부 도구)
- **ACP** — 에이전트가 **에디터(호스트 UI)**에 자신을 표시하는 방식을 표준화 (에디터 ↔ 에이전트)

즉 MCP는 "에이전트가 무엇을 쓸 수 있는가"를, ACP는 "에이전트가 어디에 나타날 수 있는가"를 표준화합니다. 서로 대체 관계가 아니라 같은 에이전트가 둘 다 지원할 수 있는 별개의 축입니다.

## 왜 필요한가

ACP가 없으면 [[Cline]]처럼 "VSCode 전용으로 짜여진" 에이전트는 JetBrains에서 못 쓰고, 반대로 JetBrains용으로 만들면 VSCode에서 못 씁니다. 에디터마다 통합 코드를 새로 짜야 하는 이 문제가, [[함수 호출 (Tool Use)#표준화된 도구 정의 — MCP로 이어지는 문제|도구 정의를 애플리케이션마다 새로 구현해야 했던 문제]]와 구조적으로 같습니다 — 다만 이번엔 "도구"가 아니라 "에디터"가 표준화 대상입니다.

ACP 서버 하나(에이전트 쪽)만 구현해두면, ACP를 말할 수 있는 어떤 에디터(클라이언트)든 별도 통합 없이 그 에이전트를 그대로 띄웁니다.

## 실제로 뭘 표시하나

- 채팅 메시지
- 도구 호출 활동
- 파일 diff (승인 전까지는 실제로 쓰기 전 상태)
- 터미널 명령 실행 결과
- 승인(approval) 요청

## 관련
- [[Hermes Agent]] — ACP로 여러 에디터를 동시 지원하는 대표 사례
- [[MCP (Model Context Protocol)]] — 방향이 다른 표준화 프로토콜(도구 쪽)
- [[Cline]] · [[Continue.dev]] — ACP 없이 특정 에디터에 고정된 기존 방식의 비교 대상
