# 스케일과 제로포인트

[[양자화]]에서 실수(FP16) [[가중치]]를 정수로 바꿔 저장할 때, 나중에 원래 값 근처로 복원하기 위해 쓰는 변환 공식입니다.

```
실제값 ≈ scale × (정수값 − zero_point)
```

- **scale** — 정수 1칸이 실제로 얼마만큼의 차이를 나타내는지. 보통 `(최댓값 − 최솟값) / (표현 가능한 정수 범위)`로 계산합니다.
- **zero_point** — 실수 0이 정수 축의 어디에 오는지 맞춰주는 보정값.

## 대칭 vs 비대칭 — "대칭"이 정확히 뭘 말하나

여기서 대칭은 **실수 범위와 정수 범위가 둘 다 0을 중심으로 좌우 대칭**이라는 뜻입니다. 그룹에서 절댓값이 가장 큰 값(`max_abs`)을 구해 실수 범위를 `[-max_abs, +max_abs]`로 놓고, 정수 범위도 0을 중심으로 대칭(예: 4비트면 대략 -7~7)으로 잡은 뒤 `zero_point`를 정확히 0으로 고정합니다 — 정수 0이 항상 실수 0에 정확히 대응하는 겁니다.

예를 들어 실제 값이 -0.42~+0.51이라면, 대칭 양자화는 더 큰 쪽인 0.51을 기준 삼아 `[-0.51, +0.51]`을 씁니다. 음수 쪽은 실제로 -0.42까지밖에 안 가는데 -0.51까지 여유를 두는 셈이라 약간 낭비가 있지만, zero_point가 0이라 계산(뺄셈 한 번)을 아낄 수 있습니다.

**비대칭 양자화**는 진짜 `[min, max]`를 그대로 쓰고 zero_point를 0이 아닌 값으로 계산합니다. ReLU 이후 활성값처럼 값이 항상 0 이상으로 한쪽에 쏠려 있으면, 대칭으로 억지로 `[-max,+max]`를 잡을 경우 정수 범위 절반을 "절대 안 나오는 음수"에 낭비하게 되므로 비대칭이 훨씬 효율적입니다. [[가중치]]는 학습 중 weight decay 같은 규제가 양쪽에서 0으로 밀어붙여 대체로 0 중심으로 고르게 분포하므로, 대칭 양자화로도 손실이 작고 계산도 더 싸서 가중치엔 대칭·활성값엔 비대칭을 쓰는 게 일반적입니다.

**왜 그룹 단위로 쪼개서 하나** — scale 하나를 가중치 행렬 전체에 쓰면, 값이 유난히 큰 채널 하나 때문에 scale이 커져버려 나머지 채널이 정밀도를 낭비합니다. 32~128개씩 묶어(per-group) 그룹마다 별도 scale을 두면 저장 비용은 조금 늘어도 정밀도 손실이 훨씬 줄어듭니다 — [[GGUF]]의 "Q4_K_M" 같은 이름의 "K"가 이 블록 단위 방식(k-quants)을 가리킵니다.

## 관련

- [[GGUF]] — 그룹(블록) 단위 스케일을 실제로 쓰는 포맷
- [[AWQ]] · [[GPTQ]] — 이 기본 공식 위에 정확도를 더 지키기 위한 기법을 얹은 두 방식
