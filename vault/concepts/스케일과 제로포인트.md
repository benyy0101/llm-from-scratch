# 스케일과 제로포인트

[[양자화]]에서 실수(FP16) [[가중치]]를 정수로 바꿔 저장할 때, 나중에 원래 값 근처로 복원하기 위해 쓰는 변환 공식입니다.

```
실제값 ≈ scale × (정수값 − zero_point)
```

- **scale** — 정수 1칸이 실제로 얼마만큼의 차이를 나타내는지. 보통 `(최댓값 − 최솟값) / (표현 가능한 정수 범위)`로 계산합니다.
- **zero_point** — 실수 0이 정수 축의 어디에 오는지 맞춰주는 보정값.

## 대칭 vs 비대칭 — "대칭"이 정확히 뭘 말하나

여기서 대칭은 **실수 범위와 정수 범위가 둘 다 0을 중심으로 좌우 대칭**이라는 뜻입니다. 그룹에서 절댓값이 가장 큰 값(`max_abs`)을 구해 실수 범위를 `[-max_abs, +max_abs]`로 놓고, 정수 범위도 0을 중심으로 대칭(예: 4비트면 대략 -7~7)으로 잡은 뒤 `zero_point`를 정확히 0으로 고정합니다 — 정수 0이 항상 실수 0에 정확히 대응하는 겁니다.

예를 들어 실제 값이 -0.42~+0.51이라면, 대칭 양자화는 더 큰 쪽인 0.51을 기준 삼아 `[-0.51, +0.51]`을 씁니다. 음수 쪽은 실제로 -0.42까지밖에 안 가는데 -0.51까지 여유를 두는 셈이라 약간 낭비가 있지만, zero_point가 0이라 계산(뺄셈 한 번)을 아낄 수 있습니다.

**비대칭 양자화**는 진짜 `[min, max]`를 그대로 쓰고 zero_point를 0이 아닌 값으로 계산합니다. ReLU 이후 활성값처럼 값이 항상 0 이상으로 한쪽에 쏠려 있으면, 대칭으로 억지로 `[-max,+max]`를 잡을 경우 정수 범위 절반을 "절대 안 나오는 음수"에 낭비하게 되므로 비대칭이 훨씬 효율적입니다. [[가중치]]는 학습 중 weight decay 같은 규제가 양쪽에서 0으로 밀어붙여 대체로 0 중심으로 고르게 분포하므로, 대칭 양자화로도 손실이 작고 계산도 더 싸서 가중치엔 대칭·활성값엔 비대칭을 쓰는 게 일반적입니다.

**왜 그룹 단위로 쪼개서 하나** — scale 하나를 가중치 행렬 전체에 쓰면, 값이 유난히 큰 채널 하나 때문에 scale이 커져버려 나머지 채널이 정밀도를 낭비합니다. 32~128개씩 묶어(per-group) 그룹마다 별도 scale을 두면 저장 비용은 조금 늘어도 정밀도 손실이 훨씬 줄어듭니다 — [[GGUF]]의 "Q4_K_M" 같은 이름의 "K"가 이 블록 단위 방식(k-quants)을 가리킵니다.

## PTQ vs QAT — 언제 양자화하는가

지금까지 다룬 scale·zero_point 계산은 전부 **학습이 끝난 뒤** 가중치에 사후 적용하는 방식(PTQ, Post-Training Quantization)입니다. 캘리브레이션용 샘플 128~1024개만 있으면 몇 분~몇 시간 안에 끝나고, [[GPTQ]]·[[AWQ]] 둘 다 PTQ 계열입니다.

반대로 **QAT(Quantization-Aware Training)**는 학습 순전파 과정 자체에 양자화 연산(반올림)을 끼워 넣어, 모델이 애초에 "반올림해도 오차가 작은 자리"에 가중치가 놓이도록 학습하게 만듭니다. 전체 학습을 다시 돌려야 하는 만큼 비용이 훨씬 크지만, 4비트까지 눌러도 손실이 1% 미만으로 PTQ(대개 1~3% 손실)보다 정확도를 더 잘 지킵니다. 실무에서는 "일단 PTQ로 눌러보고, 정확도 저하가 용인 범위를 넘으면 QAT를 고려한다"는 순서가 일반적입니다 — QAT는 원본 학습 파이프라인에 접근할 수 있어야만 가능하기 때문입니다.

## GPTQ가 오차를 보정하는 방법 — Hessian과 오차 전파

단순히 각 가중치를 scale대로 반올림만 하면(위 기본 공식) 가중치 하나하나의 반올림 오차는 작아도, 그 오차들이 다음 층 활성화값에 누적돼 결과적으로 모델 출력이 무시 못 할 만큼 틀어질 수 있습니다. [[GPTQ]]는 이 문제를 두 가지 장치로 줄입니다.

1. **Hessian 기반 중요도 판단** — 캘리브레이션 데이터로 각 가중치에 대한 손실의 2차 미분(Hessian) 근사값을 구합니다. Hessian이 큰 가중치는 "이 값이 조금만 틀어져도 출력이 크게 흔들린다"는 뜻이라 더 신중하게(가능한 한 원래 값에 가깝게) 반올림하고, Hessian이 작은 가중치는 다소 거칠게 반올림해도 됩니다.
2. **오차 보상(error compensation)** — 한 열(column)을 양자화하고 나면 반올림으로 생긴 오차를 그냥 버리지 않고, 아직 양자화하지 않은 나머지 열들에 Hessian으로 가중치를 매겨 되돌려줍니다. 즉 "이번 열에서 발생한 오차 중 다음 열이 흡수할 수 있는 만큼을 다음 열의 값에 미리 반영"하는 방식으로, 열 하나하나의 오차가 뒤로 갈수록 누적되는 대신 서로 상쇄되도록 유도합니다.

이 두 장치 덕분에 GPTQ는 단순 반올림보다 훨씬 낮은 손실로 INT4까지 압축할 수 있습니다. [[AWQ]]는 접근 방식이 조금 다른데, "활성화값이 유난히 큰 채널에 곱해지는 가중치(전체의 약 1%)"가 출력에 불균형하게 큰 영향을 준다는 관찰에서 출발해, 그 채널들만 양자화 전에 스케일을 키웠다가 계산 후 다시 낮추는 방식으로 정밀도를 지킵니다 — GPTQ가 "오차를 사후에 보정"한다면, AWQ는 "애초에 중요한 채널이 덜 다치게 미리 스케일을 조정"하는 접근입니다.

값의 민감도는 위치마다도 다릅니다. 가중치는 INT4까지도 비교적 잘 버티지만, [[KV 캐시]]에 들어가는 값이나 어텐션 소프트맥스 직전의 로짓은 아주 작은 양자화 오차([[Query·Key·Value|어텐션]] 확률분포를 의미 있게 바꿀 만큼)에도 민감해서 실무에서는 이 부분만 더 높은 정밀도(FP16·INT8)로 남겨두는 경우가 많습니다.
