# PII 마스킹

사용자가 LLM에 보내는 프롬프트나 LLM이 돌려주는 응답에 전화번호·계좌번호·이메일·이름 같은 개인식별정보(PII)가 섞여 있을 때, 이를 모델에 도달하기 전(또는 로그에 남기 전)에 탐지해 가리는 처리를 말합니다. [[RAG]]가 "문서에 들어있는 개인정보"를 반입 단계에서 걸러내는 문제라면, PII 마스킹은 "사용자가 대화창에 직접 입력하는 개인정보"를 게이트웨이 단에서 걸러내는 문제라 — 같은 목표(개인정보 유출 방지)를 서로 다른 지점에서 다룹니다.

[[LiteLLM]] 같은 [[모델 서빙과 서비스 배포|API 게이트웨이]]는 이 처리를 "가드레일(guardrail)"이라는 이름의 콜백 단계로 제공하는 경우가 많고, 완전 폐쇄망 환경에서는 외부 API를 호출하는 상용 가드레일 대신 [[Presidio]]처럼 컨테이너로 자체 호스팅 가능한 도구를 씁니다. 탐지된 개체는 보통 `MASK`(가려서 표시)하거나 `BLOCK`(요청 자체를 거부)하는 두 가지 방식 중 하나로 처리됩니다.

한국어 환경에서는 주의할 점이 하나 있는데, 범용 PII 탐지 모델이 영어권 개체명(사람 이름 등) 위주로 학습돼 있어 한국어 인명 인식률이 낮은 경우가 많습니다. 전화번호·계좌번호처럼 형식이 뚜렷한 정보는 정규식 기반 커스텀 인식기로 보완하는 게 실용적인 절충안입니다.
