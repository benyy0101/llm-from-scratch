# DGX 멀티노드 아키텍처

GPU가 노드 한 대로 끝나지 않고 [[GPU 선택|DGX]] 여러 대로 늘어나면, "한 대짜리 노드에 어떤 모델을 올릴까"였던 질문이 "**노드 간 연결이 어떻게 돼 있느냐**"라는 새로운 질문으로 바뀝니다.

## 노드 내부 vs 노드 간 연결은 완전히 다른 대역폭

- **노드 내부(같은 DGX 안, 보통 8장 GPU)** — NVLink로 묶여 있어 GPU끼리 통신이 매우 빠름. [[Tensor Parallelism]]으로 큰 모델 하나를 이 8장에 쪼개 올리는 게 효율적.
- **노드 간(DGX 여러 대 사이)** — InfiniBand 같은 전용 고속 패브릭으로 하나의 슈퍼포드처럼 묶여 있지 않은 이상, 보통 일반 이더넷 수준입니다. 이 경우 **여러 노드에 걸친 텐서 병렬화는 비효율적**입니다 — 통신 지연이 병목이 되어 노드 내부 대비 대역폭이 훨씬 낮기 때문입니다.

"DGX 4대가 같은 폐쇄망 안에서 연결돼 있다"는 말은 API 레벨 통신(HTTP 요청)은 되지만, 모델 하나를 4개 노드에 쪼개는 저수준 텐서 병렬화까지 빠르게 되는 건 아니라는 뜻입니다. 이 둘을 헷갈리면 "노드가 4대나 있으니 1.5TB짜리 초거대 모델도 되겠지"라고 잘못 계산하게 됩니다.

## 그래서 나오는 원칙 — "노드 1대 = 완결된 서비스 하나"

노드 간에 저수준 병렬화를 걸지 않고, 각 노드가 자체 8-GPU 안에서 [[Tensor Parallelism|텐서 병렬화]]로 모델 하나를 온전히 서빙하게 합니다. 노드 간에는 [[LiteLLM]] 게이트웨이가 API 레벨에서 라우팅만 해주는 구조입니다.

```
노드 #1 (8x GPU, NVLink) — 메인 코딩/문서 모델 완결 서빙
노드 #2 (8x GPU, NVLink) — 임베딩+리랭커 전용
노드 #3 (8x GPU, NVLink) — 메인 모델 이중화(HA) 복제본
노드 #4 (8x GPU, NVLink) — 신규 모델 실험/스테이징
        ↑ 노드 간은 이더넷 + LiteLLM API 라우팅만
```

## 세대에 따라 노드 하나의 체급이 달라짐

FP16(무양자화) 기준, 8-GPU 노드 하나에 무리 없이 올릴 수 있는 모델 크기는 GPU 세대마다 다릅니다.

| GPU (8장 노드) | GPU당 VRAM | 노드 총 VRAM | 무양자화로 여유 있는 모델 |
|---|---|---|---|
| A100 | 80GB | 640GB | ~70B급 (Llama 3.1 70B, Qwen2.5-72B) |
| H100 | 80GB | 640GB | A100과 동급 + [[FP8]] 네이티브로 더 큰 모델도 실용적 |
| B200/B100 | 192GB | 1.5TB | 235B급([[MoE (Mixture of Experts)|MoE]])까지 FP8로 여유, 405B급도 시도 가능 |

405B급(Llama 3.1 405B, FP16 기준 ~810GB) 같은 초거대 모델은 A100/H100 노드 한 대로는 불가능하고, 진짜로 노드를 넘나드는 멀티노드 서빙이 필요합니다 — 이때 비로소 앞서 말한 "노드 간 저대역폭 병목" 문제가 실제로 발목을 잡습니다.
