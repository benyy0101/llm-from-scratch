# 토큰

모델은 글자가 아니라 **토큰** 단위로 텍스트를 자릅니다. 영어는 대략 단어 하나가 토큰 1개 안팎이지만, 한국어는 조사·어미 때문에 같은 글자 수라도 토큰이 더 많이 소모되는 경향이 있습니다. [[Prefill과 Decode|Decode]] 단계는 이 토큰을 한 번에 하나씩만 생성합니다.

## 왜 글자 단위도 단어 단위도 아닌가

단어 단위(공백 기준 분할)로 자르면 어휘 사전이 무한정 커집니다(영어만 따져도 단어형이 100만 개 가까이 나옴) — 사전에 없는 단어는 전부 `[UNK]` 하나로 뭉개져 의미가 사라집니다. 반대로 글자 단위로 자르면 사전은 수백 개로 작아지지만, 문장 하나가 토큰 수십~수백 개로 늘어나 [[컨텍스트 윈도우]]를 순식간에 다 씁니다. 두 극단 사이에서 "자주 나오는 덩어리는 토큰 하나로, 드문 단어는 여러 조각으로" 쪼개는 절충안이 **서브워드 토큰화**이고, 그 학습 알고리즘이 BPE(Byte Pair Encoding)입니다.

## BPE — 병합 규칙을 어떻게 학습하는가

BPE는 "가장 자주 붙어 나오는 인접 쌍을 반복해서 하나로 합친다"는 탐욕적(greedy) 알고리즘입니다. 학습 결과물은 모델 가중치가 아니라 **병합 순서가 기록된 규칙 목록**(merge table) 하나입니다.

1. 말뭉치를 일단 가장 작은 단위(바이트 또는 글자)로 전부 쪼갭니다.
2. 지금 남아있는 모든 인접 쌍의 등장 횟수를 센다.
3. 가장 많이 등장한 쌍 하나를 새 토큰 하나로 합친다 — 예를 들어 `lower`(5회), `lowest`(2회), `newest`(6회)로 이뤄진 말뭉치라면 `(w,e)` 쌍이 13회로 가장 많이 나와서 제일 먼저 `we`라는 새 토큰으로 합쳐집니다.
4. 합친 결과 위에서 다시 인접 쌍을 세면 `(we,s)`처럼 방금 만든 토큰이 낀 새로운 쌍이 나타납니다. 목표 어휘 크기(예: 32,000개)에 도달할 때까지 2~4를 반복합니다.

핵심은 **병합이 일어난 순서 자체가 곧 규칙**이라는 점입니다. 인코딩할 때는 새 텍스트를 다시 최소 단위로 쪼갠 뒤, 학습 때 병합된 순서 그대로 규칙을 적용해나갑니다 — 같은 쌍이라도 먼저 등록된 병합이 우선합니다.

```
말뭉치: l o w e r (x5) / l o w e s t (x2) / n e w e s t (x6)
1회차: (w,e) 13회 최다 → we 로 병합
2회차: (we,s) 8회 최다 → wes 로 병합
...
```

GPT-2/GPT-3/GPT-4 계열은 문자가 아니라 **UTF-8 바이트(0~255)**를 최소 단위로 시작합니다("바이트 레벨 BPE"). 어떤 언어·이모지·특수문자든 결국 바이트로는 표현되므로, 이 방식은 원리적으로 `[UNK]`(미등록어) 토큰이 발생할 수 없습니다 — 사전에 없는 단어도 등록된 바이트 조각들로 잘게 쪼개져 표현될 뿐입니다.

## 어휘 크기가 커지는 추세

| 모델 | 어휘 크기 | 단어당 평균 토큰 수 |
|---|---|---|
| GPT-2 | 50,257 | ~1.3 |
| Llama 2 | 32,000 | ~1.4 |
| GPT-4 | ~100,256 | ~1.2 |
| Llama 3 | 128,256 | ~1.1 |
| GPT-4o | 200,019 | ~1.0 |

어휘를 키우면 임베딩 행렬(어휘 크기 × 은닉 차원)은 커지지만, 같은 글을 표현하는 데 필요한 토큰 수가 줄어 [[Prefill과 Decode|Decode]] 단계에서 생성해야 할 토큰 자체가 적어지고 [[컨텍스트 윈도우]]도 실질적으로 늘어난 효과를 봅니다. 다만 이 이득은 언어마다 불균등합니다 — 학습 말뭉치가 영어 위주면 병합 규칙도 영어 패턴 위주로 학습되어, 같은 의미의 한국어 문장이 영어 문장보다 토큰을 2~3배 더 많이 소모하는 경우가 흔합니다(Llama 3가 비라틴 문자 어휘를 기존 대비 4배로 늘린 이유 중 하나).
