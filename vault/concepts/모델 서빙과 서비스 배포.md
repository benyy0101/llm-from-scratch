# 모델 서빙과 서비스 배포

"모델을 서빙한다"는 말은 좁은 의미로는 정확합니다 — [[vLLM]]이나 [[Ollama]] 같은 엔진이 하는 일, 즉 [[가중치]]를 GPU에 올려두고 [[배치]]·[[PagedAttention]] 같은 최적화로 추론 요청에 응답하는 것 자체를 가리키는 말이기 때문입니다. 틀린 건 "서비스를 배포한다"를 "모델 서빙 하나만 띄우면 끝"이라고 착각하는 경우입니다.

[[RAG]]를 곁들인 실제 서비스라면 최소한 이 정도가 동시에 떠 있어야 합니다.

- **LLM 서빙** — 답변을 생성하는 모델
- **임베딩 서빙** — [[임베딩과 벡터DB|문서·질문을 벡터로 바꾸는]], LLM과는 별개인 또 다른 모델
- **벡터DB** — 서빙이 아니라 영구 저장이 필요한 상태 저장 서비스
- **API 게이트웨이·오케스트레이션** — 검색 결과와 질문을 합쳐 프롬프트를 만들고, 인증·라우팅을 처리하는 코드

이 중 진짜 "모델 서빙"이라 부를 수 있는 건 앞의 두 개(LLM, 임베딩)뿐이고, 나머지는 성격이 다른 컴포넌트입니다 — [[표준 아키텍처]] 다이어그램이 서빙 엔진·벡터DB·API 게이트웨이를 애초에 서로 다른 박스로 그려둔 이유가 이것입니다. "모델 서빙"이라는 말은 이 중 한 조각만 정확히 가리키는 좁은 용어이지, 배포 전체를 뜻하는 말이 아닙니다.

## 관련
- [[표준 아키텍처]] — 이 구분이 실제 다이어그램으로 그려진 형태
- [[RAG]] — 이 구분이 가장 뚜렷하게 드러나는 사례
- [[임베딩과 벡터DB]] — 모델 서빙이 아닌, 영구 상태를 갖는 컴포넌트의 예
- [[vLLM]] · [[Ollama]] — 정확히 "모델 서빙"에 해당하는 것
- [[전통 서버 서빙과의 차이]] — "서빙"이라는 단어 자체가 가리키는 범위에 대한 다른 관점
