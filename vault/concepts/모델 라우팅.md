# 모델 라우팅

여러 [[모델과 엔진|모델]]을 동시에 서빙해두고, 요청마다 난이도·비용에 맞는 모델로 자동 배분하는 방식입니다. 간단한 질문("연차는 며칠이야?")은 작고 빠른 모델로, 복잡한 질문(여러 규정을 엮어 추론해야 하는 질문)은 크고 느린 모델로 보내면, 큰 모델 하나에 모든 트래픽을 몰아주는 것보다 같은 GPU 자원으로 더 많은 요청을 처리할 수 있습니다.

같은 모델의 여러 복제본 사이에 부하를 나누는 **로드밸런싱**(예: [[LiteLLM]] Router의 `simple-shuffle`, `least-busy` 전략)과는 다른 개념입니다. 로드밸런싱은 "누가 덜 바쁜가"를 보고, 모델 라우팅은 "이 요청이 어느 모델에 맞는가"를 봅니다.

난이도 판단(classifier) 방식은 대표적으로 두 가지입니다.

- **휴리스틱 분류** — 정규식·키워드 기반. 지연시간이 거의 없고 외부 호출도 필요 없어 완전 [[폐쇄망]]에서도 문제없이 씁니다.
- **LLM 기반 분류** — 별도 모델(또는 같은 모델)에게 "이 질문 난이도가 어느 정도야?"를 물어봄. 더 정교하지만 판별 자체가 추가 모델 호출이라 지연시간이 늘어납니다.

## 관련
- [[시맨틱 캐싱]] — 같은 목표(제한된 GPU 자원으로 늘어난 트래픽 처리)를 다른 방식으로 달성하는 짝
- [[Tensor Parallelism]] — 큰 모델과 작은 모델을 별도 GPU에 나눠 배치할 때 함께 고려하는 배치 문제
- [[Goodput]] — 라우팅 분류기의 방식(휴리스틱 vs LLM)이 곧 지연시간 예산과 직결되는 지점
- [[LiteLLM]] — 이 기능을 게이트웨이 설정으로 제공하는 도구
