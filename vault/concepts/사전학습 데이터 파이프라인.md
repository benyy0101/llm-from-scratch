# 사전학습 데이터 파이프라인

[[사전학습(Pretraining)]]에 들어가는 텍스트는 인터넷에서 긁어온 그대로 쓰이지 않습니다. Common Crawl 원본(약 250TB)은 광고·내비게이션 메뉴·기계 생성 스팸이 뒤섞인 "더러운" 데이터라, 실제로 학습에 쓰기까지 여러 단계의 정제를 거칩니다. Llama 팀 기준으로 이 정제 과정에서 원본의 상당 부분(중복 제거 단계만으로도 약 38%)이 걸러진다고 알려져 있습니다.

## 정제 파이프라인 6단계

1. **텍스트 정제** — HTML 태그·자바스크립트·보일러플레이트 제거, 공백 정규화.
2. **품질 필터링** — 너무 짧은 문서, SEO 스팸(과도한 대문자·키워드 나열), 특수문자 비율이 비정상적으로 높은 기계 생성 콘텐츠를 제외. 작은 언어모델의 [[LLM 평가|perplexity]]로 "이 문서가 자연스러운 글인가"를 가늠하는 방식도 씁니다.
3. **중복 제거** — 문서를 n-gram 조각("shingle")으로 변환해 서명을 만들고(MinHash), 유사도가 높은(Jaccard 0.8 이상) 문서를 제거합니다. 완전히 같은 문서가 아니라 "거의 같은" 근접 중복까지 잡아내는 게 핵심입니다.
4. **언어 감지** — 문장 단위 분류기(fastText 등)로 언어를 판별하고, 신뢰도가 낮은 문서는 걸러냅니다.
5. **토큰화·패킹** — 문서를 [[토큰]]으로 바꾼 뒤, 여러 문서를 이어붙여 고정 길이(예: 2048/4096 토큰) 시퀀스로 채웁니다. 문서 하나가 짧다고 남는 자리를 패딩으로 낭비하지 않고, 다음 문서를 이어 붙이되 attention mask로 문서 경계를 표시해 서로 못 보게 막습니다.
6. **셔플·배치화** — 시퀀스 순서를 무작위로 섞어 배치로 묶습니다. 같은 도메인·같은 시점 문서가 몰려서 배치를 이루면 학습이 편향될 수 있어서입니다.

## 데이터 구성의 실제 예 — Llama 3

Llama 3는 15.6조 토큰을 웹 데이터 50%, 코드 25%, 도서/논문 13%, 수학 8%, 다국어 4%로 구성했다고 알려져 있습니다. "얼마나 많은 데이터를 모았나"만큼 "어떤 비율로 섞었나"가 결과 모델의 능력(코드 실력, 수학 실력 등)을 직접 좌우합니다.

## 왜 데이터 양과 모델 크기의 비율이 중요한가

Chinchilla 스케일링 연구는 "모델 파라미터 수와 학습 토큰 수를 특정 비율로 맞춰야 같은 컴퓨팅 예산에서 최적 성능이 나온다"는 결과를 보였습니다. GPT-3(175B, 학습 토큰 3000억)는 이 비율 기준으로 상당히 "과소학습"된 모델로 꼽히고, 반대로 최근 추세는 "추론 비용을 아끼기 위해 일부러 작은 모델을 기준보다 훨씬 많은 토큰으로 학습"하는 쪽으로 가고 있습니다 — 데이터 파이프라인이 감당해야 할 데이터 양 자체가 이 선택에 따라 달라집니다. 자세한 원리는 [[스케일링 법칙]] 참고.
