# 카오스 엔지니어링

시스템에 의도적으로 장애를 주입해, 실제 장애가 나기 전에 복원력(장애 상황에서도 서비스가 어디까지 버티는지)을 확인하는 방법론입니다. 부하 테스트가 "정상 상태에서 트래픽을 늘리면 어디서 무너지는가"를 본다면, 카오스 엔지니어링은 "무언가 이미 고장 났을 때 나머지가 어디까지 버티는가"를 봅니다.

Kubernetes 기반 도구(Chaos Mesh, LitmusChaos)가 널리 쓰이지만 둘 다 K8s 컨트롤 플레인을 전제로 합니다. [[Podman]] 기반 온프레미스 환경처럼 오케스트레이션 레이어가 없는 경우엔, 컨테이너 런타임에 직접 개입하는 도구(Pumba 등)나 리눅스 커널 기능(`tc netem`, `iptables`)으로 직접 장애를 주입하는 게 현실적입니다. 다만 rootless 컨테이너에서는 네트워크·리소스에 개입하는 종류의 주입(지연·패킷 손실·CPU 스트레스)이 권한 부족으로 실패하는 경우가 있어, 이런 테스트만 일시적으로 rootful로 전환했다가 테스트 후 되돌리는 방식이 자주 쓰입니다.

GPU 서빙 인프라에 특화된 부분도 있습니다. NVIDIA DCGM의 오류 주입 기능은 실제 하드웨어 장애가 아니라 **모니터링·알람 파이프라인이 오류 신호에 제대로 반응하는지**를 검증하는 용도이고, 실제 하드웨어 장애는 커널이 `dmesg`에 남기는 XID 에러 코드(예: 79 = GPU가 버스에서 이탈)로 사후 진단하는 경우가 많습니다.
