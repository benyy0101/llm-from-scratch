# DPO

[[RLHF]]는 보상 모델을 따로 학습시키고, 그 보상 모델의 신호로 PPO 강화학습을 또 한 번 돌려야 해서 모델을 3~4벌(SFT 모델·보상 모델·정책·참조 모델) 동시에 메모리에 올려야 하고 하이퍼파라미터에도 예민합니다. DPO는 "언어모델 자체가 사실 보상 모델을 암묵적으로 담고 있다"는 통찰에서 출발해, 보상 모델 학습과 PPO 단계를 통째로 건너뛰고 선호도 데이터에서 **지도학습 하나로** 곧장 정책을 최적화합니다.

## 핵심 통찰 — 보상을 정책 자체의 확률비로 표현하기

RLHF의 PPO가 최적화하는 목적함수를 수학적으로 풀어보면, 최적 정책에서 보상은 정책과 참조모델의 로그 확률비로 정확히 표현된다는 사실이 나옵니다.

```
R(x, y) = β · log( π(y|x) / π_ref(y|x) ) + 상수
```

즉 "보상이 얼마인가"를 별도 모델로 다시 학습할 필요 없이, 지금 학습 중인 정책 자신의 확률과 원래 참조모델의 확률을 비교하는 것만으로 보상을 대신할 수 있습니다.

## DPO 손실 함수

이 관계를 [[RLHF]]에서 쓴 보상 모델 손실(Bradley-Terry 형태)에 대입하면, 별도의 보상 모델 없이 정책 하나만으로 계산되는 손실식이 나옵니다.

```
loss = -log( sigmoid( β · [ log(π(y_승|x)/π_ref(y_승|x)) − log(π(y_패|x)/π_ref(y_패|x)) ] ) )
```

- `y_승` — 사람이 선호한 응답, `y_패` — 선호하지 않은 응답
- `β` — 참조모델에서 얼마나 벗어나도 되는지를 조절하는 값(RLHF의 KL 페널티 β와 같은 역할)

이 손실을 최소화하면 선호 응답의 (참조모델 대비) 상대 확률은 올라가고 비선호 응답의 상대 확률은 내려갑니다 — RLHF가 "보상 모델 학습 → PPO로 정책이 그 보상을 쫓게 함"이라는 두 단계로 하던 일을, DPO는 한 번의 지도학습 손실로 압축한 셈입니다.

## RLHF 대비 무엇이 줄고 무엇을 잃는가

| 항목 | RLHF | DPO |
|---|---|---|
| 필요 모델 수 | 3~4개(SFT·보상·정책·참조) | 2개(정책·참조) |
| 학습 루프 | 보상 모델 학습 + PPO, 2회 | 지도학습 1회 |
| 안정성 | 하이퍼파라미터에 민감 | 지도학습 수준으로 안정적 |
| 다차원 보상 | 여러 신호를 보상 모델에 섞어 반영 가능 | 선호 쌍 하나로 단순화됨 |

DPO는 데이터가 적고(5천~2만 쌍) 계산 자원이 제한적일 때, 그리고 빠르게 반복 실험을 돌려야 할 때 유리합니다. 반대로 여러 축의 보상 신호(안전성·유용성·간결함 등)를 따로 설계해 섞어야 하거나, 대규모로 온라인으로 반복해서 정렬해야 하는 최상위권 모델(GPT-4·Claude급)은 여전히 RLHF의 유연성이 필요합니다. 실제로 Llama 3는 RLHF로 먼저 정렬한 뒤 DPO로 한 번 더 다듬는 식으로 두 방법을 함께 씁니다.
