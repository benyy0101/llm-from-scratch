# 전통 서버 서빙과의 차이

일반적인 REST API/웹서버 서빙과 LLM 서빙은 겉모습(HTTP 요청 → 응답)은 같아도 내부 동작 방식이 근본적으로 다릅니다. 이 노트는 그 차이를 만드는 개별 개념들을 모으는 허브입니다.

| 항목 | 일반 API 서버 | LLM 서빙 |
|---|---|---|
| 요청당 처리 비용 | 균일 | [[Prefill과 Decode\|프롬프트·생성 길이에 따라 편차]] |
| 상태 | Stateless | [[Stateful 서빙\|KV 캐시가 GPU에 물려 사실상 stateful]] |
| 응답 방식 | 단발 요청-응답 | [[스트리밍 응답]] |
| 로드밸런싱 | 라운드로빈으로 충분 | [[Continuous Batching\|큐·메모리 여유 기반 자체 스케줄링]] |
| 확장 단위 | 수평(레플리카), 초 단위 | 수직(배치 극대화) 우선, GPU 추가는 분 단위 |
| 캐싱 | 결과 캐싱이 잘 먹힘 | [[PagedAttention\|prefix/페이지 캐싱으로 대체]] |

결국 [[vLLM]] 같은 엔진은 전통 인프라의 로드밸런서·오토스케일러·캐시 레이어 역할을 GPU 메모리라는 유한 자원 제약 안에서 엔진 하나가 떠안는 것에 가깝습니다.
