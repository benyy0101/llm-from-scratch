# EP19. GPU 증설 — DGX B200과 멀티모델 서빙

> 시리즈: [폐쇄망 LLM 구축기](README.md) · 이전: [EP18. 시리즈 총정리 & 운영 회고](EP18-시리즈-총정리-운영-회고.md) · 다음: [EP20. 에이전트 심화 — Cline과 Tool-Use 벤치마크](EP20-에이전트-심화-Cline-BFCL.md)

EP18에서 "전사 확대되면 V100 3장으로는 부족할 거고, A100 증설을 다시 품의해야겠죠"라고 썼었는데, 실제로 품의가 올라간 물건은 A100이 아니라 **DGX B200 4대**였습니다. 정보보호위원회 심의보다 예산 심의가 더 오래 걸렸다는 후일담은 생략하고, 실제로 뭘 어떻게 다시 짰는지 적어볼게요.

## 📐 이번 장비, 이전과 뭐가 다른가

| | 기존 (EP03) | 신규 |
|---|---|---|
| GPU | V100 32GB × 3장 (유휴 재활용) | **DGX B200 × 4대** (노드당 8장, 장당 192GB) |
| 노드 총 VRAM | 96GB | 노드당 **1.5TB** |
| 노드 간 연결 | 해당 없음(1노드) | 같은 폐쇄망 내부 이더넷으로 연결, NVLink/InfiniBand 패브릭으로 묶인 단일 클러스터는 아님 |

가장 먼저 확인한 게 "4대가 네트워크로 연결돼 있다"는 말의 실제 의미였어요. [[DGX 멀티노드 아키텍처]]에서 정리했듯, 노드 내부(NVLink)와 노드 간(일반 네트워크) 대역폭 차이가 워낙 커서, **노드를 넘나드는 텐서 병렬화는 처음부터 고려 대상에서 뺐습니다.** 대신 "노드 1대 = 완결된 서비스 하나"를 원칙으로 잡았어요.

## 🗂️ 노드 4대, 역할부터 나눴어요

```
DGX #1 (8x B200) — 메인 모델: Qwen3-235B-A22B, FP8
DGX #2 (8x B200) — 임베딩(BGE-M3) + 리랭커(bge-reranker) 전용
DGX #3 (8x B200) — 메인 모델 이중화(HA) 복제본
DGX #4 (8x B200) — 신규 모델 실험/스테이징
        ↑ 노드 간은 이더넷 + LiteLLM API 라우팅만
```

DGX #2에 메인 모델급 노드를 통째로 배정한 게 과한가 싶었는데, [[리랭커]]를 이번에 새로 추가하기로 하면서(아래 참고) 임베딩+리랭커+검색 트래픽을 메인 코딩/문서 트래픽과 물리적으로 분리해두는 쪽이 장애 격리 측면에서 낫다고 판단했어요.

## 🔢 왜 Qwen2.5-32B에서 Qwen3-235B로 올렸나

[[FP8]] 기준 VRAM 계산이 이렇게 나왔어요.

| 모델 | FP8 필요 VRAM | DGX #1(1.5TB)에서 |
|---|---|---|
| Qwen2.5-32B (기존) | ~32GB | 여유 과다 — 신규 장비에 걸맞지 않음 |
| Qwen3-235B-A22B (MoE, 활성 22B) | ~235GB | 여유 있게 들어가고, 남는 용량으로 동시 배치·긴 컨텍스트까지 충분 |

B200은 [[FP8]]을 하드웨어 네이티브로 지원해서(Hopper 이상부터), FP16 대비 절반 용량으로도 손실이 적었습니다. [[GPU 선택]]에서 짚었던 "AWQ가 V100에서 안 된다" 같은 세대별 제약도 Blackwell부터는 전부 풀려서, 포맷 걱정 없이 [[Tool-Use 벤치마크 (BFCL)]] 상위권 모델을 그대로 올릴 수 있었던 게 이번 증설의 실질적인 소득이었어요.

## 🧩 노드 안에서도 여러 모델을 같이 띄웠어요

DGX #2 하나에 임베딩·리랭커를 같이 올리는 것부터가 [[멀티모델 서빙]]인데, 실제 설정은 EP17에서 자동완성 모델을 세 번째 vLLM 인스턴스로 얹었던 방식과 원리가 같아요 — GPU를 나눠 vLLM 프로세스를 여러 개 띄우고, LiteLLM에 각각 등록하는 겁니다.

```yaml
model_list:
  - model_name: qwen3-235b        # DGX #1, 메인
    litellm_params:
      model: openai/qwen3-235b
      api_base: http://dgx1-vllm:8000/v1
  - model_name: bge-m3            # DGX #2, 임베딩
    litellm_params:
      model: openai/bge-m3
      api_base: http://dgx2-embed:8000/v1
  - model_name: bge-reranker      # DGX #2, 리랭커
    litellm_params:
      model: openai/bge-reranker
      api_base: http://dgx2-rerank:8000/v1
```

## 🔍 리랭커, 이번에 처음 넣었어요

EP16에서 하이브리드 검색까지는 넣었는데, [[리랭커]]는 그때 V100 3장으로는 VRAM이 빠듯해 미뤄뒀던 항목이었어요. DGX #2 노드가 통째로 생기면서 bge-reranker를 얹었고, 벡터 검색으로 top-50을 추린 뒤 리랭커가 top-8로 재정렬하는 단을 하나 더 넣었습니다. 사내 QA셋으로 재채점해보니 "연차" 류 정확한 키워드 질의 말고도, 의미는 비슷하지만 실제로는 관련 없던 문단이 상위권에서 빠지는 효과가 눈에 띄었어요.

📌 **EP.19 한 줄 요약**
DGX B200 4대는 노드 간 저대역폭 때문에 "노드 1대 = 완결된 서비스 하나" 원칙으로 역할을 분리했다. FP8 네이티브 지원 덕에 메인 모델을 Qwen3-235B급으로 올렸고, 여유가 생긴 노드에 리랭커를 처음 추가해 RAG 정확도를 보완했다.
