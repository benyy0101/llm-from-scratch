# EP03. GPU 선택 가이드 — V100 vs A100 vs 소비자 GPU

> 시리즈: [폐쇄망 LLM 구축기](README.md) · 이전: [EP02. 전체 아키텍처 설계](EP02-전체-아키텍처-설계.md) · 다음: [EP04. 컨테이너 이미지 & 모델 다운로드](EP04-컨테이너-이미지-모델-다운로드.md)

EP02에서 정한 목표, 기억하시나요? 동시 15명, 첫 토큰 3초 이내. 이번 편은 이 숫자를 만족하는 GPU를 실제로 고르는 이야기예요. 결론부터 말씀드리면 — 저희는 새 GPU를 안 샀어요. 2년 전 사기 판독 모델 학습용으로 도입했다가 지금은 놀고 있는 **V100 32GB 3장**을 재활용하기로 했거든요. 이 판단까지 어떤 과정을 거쳤는지 그대로 적어볼게요.

## 🎯 후보군부터 쭉 나열해봤어요

| 구분 | 대표 GPU | VRAM | 우리 상황에서의 의미 |
|---|---|---|---|
| 소비자 GPU | RTX 4090/3090 | 24GB | NVIDIA 드라이버 EULA상 데이터센터 상업 배포 금지 — 애초에 후보가 아니었어요 |
| 검증된 구형 데이터센터 GPU | **V100 32GB** | 32GB | 이미 보유 중, 감가상각 완료, 추가 예산 없이 품의 가능 |
| 최신 프로덕션 | A100 40/80GB, H100 | 40~80GB | 성능은 가장 좋지만 신규 구매 시 조달 절차만 최소 3~4개월 |

새 GPU(A100) 구매도 당연히 검토했어요. 근데 금융권 IT 예산이라는 게 보통 연초에 딱 확정되고, 중간에 GPU 구매 건을 새로 올리면 정보보호위원회 심의 + 구매 품의 + 조달 공고까지 진짜 3~4개월이 걸리더라고요. 반면 이미 자산으로 잡혀있는 장비를 다른 용도로 전용하는 건 부서장 결재선에서 끝나요. **결국 성능보다 "지금 당장 시작할 수 있는가"가 먼저였습니다.**

## 🖥️ V100 3장으로 뭐가 되는지 계산해봤어요

Qwen2.5-32B-Instruct를 FP16으로 올리면 대략 32B × 2바이트 = 64GB가 필요해요. V100 한 장(32GB)엔 안 들어가죠. 근데 3장을 텐서 병렬화([[Tensor Parallelism]])로 묶으면 총 96GB — 가중치 64GB를 나누고도 32GB 정도가 [[KV 캐시]]랑 배치 여유분으로 남아요. 동시 15명이 각자 짧지 않은 대화를 이어가도 버틸 만한 여유죠.

```
가중치(FP16)  64GB
+ KV 캐시·배치 여유  32GB (동시 15명 기준)
─────────────────────
총 필요 VRAM   96GB  ≈  V100 32GB × 3장
```

양자화([[AWQ]] 4비트)로 24GB 안팎까지 줄이면 1장으로도 가중치는 올라가요. 근데 여기서 첫 번째 삽질이 터졌습니다.

## ⚠️ 삽질 1 — V100에서는 AWQ가 안 돌아요

AWQ로 양자화한 체크포인트를 그대로 올렸더니 이런 에러가 떴어요.

```
RuntimeError: AWQ kernel requires compute capability >= 7.5, but found 7.0 (Volta)
```

찾아보니 V100은 Volta 아키텍처(compute capability 7.0)인데, 요즘 나온 AWQ 커널은 Ampere 이후(7.5+)를 전제로 만들어져 있더라구요. AWQ가 요즘 사실상 기본값처럼 쓰이는 포맷인데, V100 같은 구형 데이터센터 GPU한테는 애초에 후보도 아니었던 거죠.

대안은 [[GPTQ]]였어요. GPTQ Int4는 애초에 Volta급 GPU에서도 돌아가게 만들어진 구현체들이 있어서, "AWQ가 더 최신이니까 무조건 우선"이라는 일반론이랑 별개로 저희 하드웨어에서는 GPTQ가 진짜 실질적인 선택지였습니다. 결국 서비스용 체크포인트는 GPTQ Int4로 준비하기로 했어요 — 이 재양자화 작업은 다음 편에서 다뤄볼게요.

두 번째로 걸린 건 FlashAttention2였어요. 최신 서빙 스택 상당수가 이걸 기본으로 깔고 가는데, 이것도 V100(Volta)은 지원 대상이 아니더라구요. [[vLLM]]은 이 경우 Triton 기반 어텐션 커널로 자동으로 대체되긴 하는데, 순정 pip 패키지가 아니라 **sm_70(V100의 compute capability) 지원을 켜서 소스에서 직접 빌드**해야 하는 경우가 많았어요 — 이 빌드 과정은 EP08에서 그대로 재현해볼게요.

## 그래서 왜 그래도 V100이냐면

정리하면 V100은 최신 카드도 아니고, 최신 커널 상당수가 아예 안 돌고, 서빙 스택도 손봐야 해요. 근데도 이걸 선택한 이유는 세 가지예요.

1. **예산·조달 절차 없이 이번 분기 안에 바로 시작할 수 있다** — 금융권에서는 이게 스펙보다 더 큰 변수였어요.
2. **GPTQ로 우회 가능하다는 걸 직접 확인했다** — 완전히 못 쓰는 하드웨어는 아니었어요.
3. **1차 목표(동시 15명, 사내 QA + 코드 자동완성)엔 충분한 여유가 있다** — 전사 확대는 그때 가서 A100 증설을 다시 품의하면 되니까요.

"이상적인 하드웨어"가 아니라 "지금 있는 걸로 목표를 만족하는가"를 기준으로 삼은 게 이번 편의 요지예요. 다음 편에서는 이 GPTQ 체크포인트랑 컨테이너 이미지를 인터넷망에서 준비해서 반입 스테이징까지 옮기는 과정을 다뤄볼게요.
