# 폐쇄망 LLM 구축기 (자체 집필판)

[hoft.tistory.com의 "폐쇄망 LLM 서바이벌" 시리즈](https://hoft.tistory.com/entry/airgap-llm-survival-ep01-why-local-llm)는 이 글 작성 시점 기준 **EP.01만 공개되어 있고 나머지 17편은 목차만 있는 상태**였습니다. 이 폴더는 그 목차 구성이 실전 감각이 좋다고 판단해, `docs/`·`vault/`에 쌓아온 내용을 실제 금융권 배포 시나리오에 적용해가며 **우리가 직접 이어 쓴 것**입니다. 원문 시리즈의 실제 후속편이 아니라, 같은 목차를 독자적으로 채운 것임을 밝혀둡니다.

## 가상 시나리오

이 시리즈 전체에서 일관되게 쓰는 설정입니다.

| 항목 | 내용 |
|---|---|
| 기관 | **A저축은행** IT인프라팀 (가상 — 실명 아님) |
| 목표 | 사내 규정·상품 매뉴얼 문서 QA 챗봇(RAG) + 개발팀용 코딩 어시스턴트 |
| 네트워크 | 완전 물리적 망분리(에어갭) |
| 장비 | 2년 전 사기 판독 모델 학습용으로 도입했다가 유휴 상태이던 **V100 32GB × 3장**, RHEL 9 |
| LLM | Qwen2.5-32B-Instruct |
| 임베딩 | BGE-M3 |
| 스택 | Podman · vLLM · Ollama · LiteLLM · Qdrant · Open WebUI · Continue.dev |

새 장비 도입 없이 유휴 자산을 재활용한다는 설정은 실제로 금융권에서 예산·조달 절차가 오래 걸릴 때 흔히 벌어지는 일이라 일부러 넣었습니다 — 그래서 "이상적인 최신 GPU"가 아니라 "지금 있는 것으로 어디까지 되나"가 이 시리즈의 실제 문제의식입니다.

## vault와의 관계

각 편은 `vault/`의 개념 노트를 실제 절차 안에서 어떻게 쓰는지 보여주는 역할입니다. 개념 자체(예: PagedAttention이 뭔지, KV 캐시가 왜 커지는지)는 vault를 참고하고, 여기서는 "그래서 실제로 뭘 설치하고 뭘 설정하는가"에 집중합니다.

## 이 시리즈가 안 다룬 삽질은?

이 시리즈는 "A저축은행" 가상 시나리오 하나가 실제로 겪은 삽질만 다룹니다. 같은 스택을 실제로 운영해본 사람들이 GitHub 이슈·공식 트러블슈팅 문서·기술 블로그에 남긴 사례는 훨씬 더 다양합니다 — [../03-트러블슈팅-딥리서치.md](../03-트러블슈팅-딥리서치.md)에서 이 시리즈가 다루지 않은 추가 함정 60여 건을 편별로 매칭해뒀습니다. 배포 전 체크리스트나 장애 발생 시 1차 검색 대상으로 활용하세요.
